# 故事版：工坊留在山上，只把椅子送下山 🪑

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「山上工坊做東西送到山下市集」的故事，幫你「感覺」出 multi-stage build、build stage、runtime stage、`COPY --from`、`--target`，以及 Go、Rust、Node 三種做法的差別。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 連工坊一起扛下山

山上住著木匠阿哥。他做的小板凳又穩又漂亮，每個星期天都要送到山下的市集賣。

一開始，阿哥的做法很笨：他在一輛大推車上蓋了一間**移動工坊** —— 鋸子、刨刀、木屑、一大堆木材、做到一半的零件，通通在車上 —— 在車上把板凳做好，然後**整輛車推下山**。

市集的人問：「你要賣的是板凳，還是這台車？」

推車重得要命，下山要推一整天。而且車上那麼多鋒利的工具，小朋友跑來跑去，很危險。

> 這就是 **單階段的 image**：編譯工具、原始碼、依賴全部留在 image 裡，~1GB，又重又多了一堆不該有的東西。

---

## 兩個地方，各做各的事

阿嬤教阿哥一個方法：

「工坊**留在山上**。你在山上把板凳做好，然後拿一個**乾淨的小籃子**，只把板凳放進去，揹下山就好。」

- **山上的工坊**：工具、木材、木屑，愛怎麼亂都可以，反正不會下山。
- **下山的小籃子**：裡面只有板凳。

從那天起，阿哥下山只揹一個小籃子。

> 這就是 **multi-stage build**：第一個 `FROM ... AS build` 是山上的工坊（有 Go 工具鏈、原始碼），第二個 `FROM alpine` 是乾淨的小籃子。最後一個 stage 才是真正送出去的 image。

---

## 只有一條小路相通

工坊和小籃子之間，只有一條**小小的山路**。要從工坊拿東西到籃子裡，一定要說清楚：「從工坊的**哪個架子**上，拿**哪一張**板凳」。

沒說的東西，一樣都不會跑進籃子。木屑不會、鋸子不會、剩下的木材也不會。

有一次阿哥說：「從工坊拿板凳。」幫忙的小弟找了半天：「工坊那麼大，板凳在哪裡？」阿哥才改口：「在**門口第三個架子上**。」

> 這就是 **`COPY --from=build /out/shorty ...`**：stage 之間唯一的通道。路徑要寫**那個 stage 裡面**的位置，不是你家的位置。

---

## 想看看工坊裡面

有一天板凳的腳做歪了，阿哥想知道問題出在哪一步。

他跟小弟說：「這次不要揹籃子下山，**做到工坊那一步就停**，讓我進去看看半成品。」

> 這就是 **`--target build`**：只 build 到某個 stage 就停，方便進去 debug。

---

## 鐵匠阿姐的「零件清單」

隔壁住著鐵匠阿姐，她做的是鐵製的小風車。她也學會了「工坊留山上」這招，但她有另一個煩惱：

每個風車要用到幾十種螺絲和齒輪。這些零件**很少換**，可是每次打造都要從頭敲，一敲就是一整個早上。改一片風車葉子，也要先把所有螺絲重敲一遍。

木匠阿哥有個好習慣：他的零件清單就寫在一張紙上，看紙就知道要準備哪些木材，可以先備好。但阿姐的設計圖裡，零件和風車畫在一起，不先讀完整張圖，不知道要哪些零件。

於是阿姐請了一個小幫手：

1. 小幫手**先讀一遍設計圖**，只抄出「需要哪些螺絲齒輪」，寫成一張**零件清單**。
2. 阿姐**照清單先把零件打好**，收在櫃子裡。
3. 最後才拿設計圖，組裝風車本身。

下次只改風車葉子時，零件清單一模一樣，櫃子裡的零件直接拿來用。

風車做好之後，阿姐也只把風車放進小籃子。不過她的風車需要一個特別的**底座**才轉得動，所以籃子裡還要放一個小底座。

> 這就是 **Rust 的 cargo-chef**：`cargo chef prepare` 是小幫手抄零件清單（`recipe.json`），`cargo chef cook` 是先把依賴編好（可以被快取），最後才 `cargo build` 自己的程式。小底座是 **glibc**，所以 runtime 用 `distroless/cc`。

## 音樂盒師傅的大箱子

第三位師傅是做音樂盒的阿伯。他做的不是一個會自己響的音樂盒，而是一捲捲**樂譜紙**，要放進一台**播放機**才會有聲音。

阿伯也試著「工坊留山上」：

- 山上：所有練習用的紙、試聽的喇叭、校音的工具。
- 下山：只帶**正式要演奏的樂譜**，練習用的紙全部丟掉。

可是不管怎麼精簡，他都**一定要揹一台播放機下山**。沒有播放機，樂譜就只是一疊紙。

所以阿伯的籃子，永遠比木匠和鐵匠的大很多。

> 這就是 **Node 的 multi-stage**：build stage 用 `npm ci` 裝全部依賴，再用 `npm prune --omit=dev` 丟掉開發用的。但 runtime 一定要有 **Node.js 本體**（播放機），所以 image 還是有兩百多 MB。

---

## 市集上比一比

星期天，三位師傅在市集碰面，把籃子放在一起比：

- 木匠阿哥：一個小籃子，裡面只有一張板凳。
- 鐵匠阿姐：一個小籃子，風車加一個小底座。
- 音樂盒阿伯：一個大箱子，樂譜加一台播放機。

大家都比以前「整輛推車推下山」輕了很多。阿伯有點不甘心：「我的箱子能不能再小一點？」

阿嬤說：「下次來比比看，**籃子本身**用什麼材料最輕。」

> 這就是 **第 09 章 base image** 的伏筆：runtime stage 要用 alpine、debian-slim、distroless 還是 scratch？

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 整輛推車推下山 | 單階段 image（~1GB） |
| 山上的工坊 | **build stage**（`FROM golang:1.26-alpine AS build`） |
| 乾淨的小籃子 | **runtime stage**（`FROM alpine:3.22`） |
| 只有小籃子下山 | 只有**最後一個 stage** 變成 image |
| 唯一相通的小山路 | **`COPY --from=build`** |
| 「門口第三個架子上」 | `COPY --from` 的路徑是**那個 stage 裡**的路徑 |
| 做到工坊那一步就停 | **`--target build`** |
| 小幫手抄零件清單 | **`cargo chef prepare`** → `recipe.json` |
| 照清單先打好零件 | **`cargo chef cook`**（依賴層，可被快取） |
| 風車的小底座 | Rust 執行檔需要的 **glibc**（`distroless/cc`） |
| 丟掉練習用的紙 | **`npm prune --omit=dev`** |
| 一定要揹的播放機 | **Node.js runtime** |
| 三個籃子大小不同 | Go ~26MB、Rust ~25MB、Node ~230MB（範例） |
| 籃子本身的材料 | 下一章的 **base image** |

---

## 一句話記住

> **工坊留在山上，只把成品放進小籃子揹下山：`AS build` 是工坊、最後一個 `FROM` 是籃子、`COPY --from` 是唯一的山路；會自己動的板凳最輕，需要播放機的音樂盒永遠比較大。**
