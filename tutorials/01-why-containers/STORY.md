# 故事版：小晴的魔法搬家箱 📦

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「小晴帶著自己的房間去住新公寓」的故事，幫你「感覺」出「在我電腦可以跑」問題、container 和 VM 的差別、共用 kernel、以及 Docker 背後那一串幫手（CLI、dockerd、containerd、runc）。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 「在我家明明睡得很好！」

小晴要去奶奶家住一個禮拜。

在自己家，她每天晚上都睡得超好：粉紅色的小夜燈、軟軟的兔子枕頭、窗邊那台會發出嗡嗡聲的小電扇，還有床頭那本一定要翻兩頁才睡得著的故事書。

到了奶奶家，奶奶很用心地準備了一張大床。可是——小夜燈是白色的、枕頭是硬的、沒有電扇、故事書也忘了帶。

小晴翻來覆去一整晚，第二天頂著黑眼圈說：「**在我家明明睡得很好啊！**」

媽媽笑著說：「因為你需要的不只是一張床，是**一整套你習慣的東西**。」

> 這就是 **「在我電腦可以跑」的問題**：程式需要的不只是程式碼本身，還有 runtime 版本、系統函式庫、設定、環境變數。換一台機器，少了任何一樣就可能壞掉。

---

## 寫一張清單，還是直接帶走？

第二次去奶奶家前，小晴寫了一張長長的清單給奶奶：「請準備粉紅色小夜燈、兔子枕頭、會嗡嗡叫的電扇、第三集故事書……」

奶奶跑了三家店，買到的小夜燈是**淺粉紅**，電扇的嗡嗡聲**比較大聲**。小晴還是睡不好。

爸爸想了一個辦法：「與其寫清單請別人照著買，不如**把你的房間直接裝進一個魔法搬家箱**，整個帶過去。」

魔法搬家箱一打開，裡面就是小晴的房間：同一盞燈、同一顆枕頭、同一台電扇、同一本書。到哪裡打開都一模一樣。

> 這就是 **container 的核心想法**：不要給對方「安裝說明」（清單），直接給對方「已經裝好的環境」（搬家箱）。程式和它需要的一切打包在一起，到哪台機器都一樣。

---

## 蓋一棟新房子，還是住進公寓的一間房？

要讓小晴有自己的空間，大人們想了兩種方法。

**方法一：在奶奶家院子裡蓋一棟小房子。** 有自己的水塔、自己的電箱、自己的大門和屋頂。非常獨立，隔壁怎麼吵都聽不到。可是蓋一棟房子要好幾個月，還要花好多錢，院子也只蓋得下兩三棟。

**方法二：奶奶家樓下就是一棟公寓，直接住進其中一間房。** 每間房有自己的門鎖、自己的家具，鄰居看不到你房間裡有什麼。但是整棟樓**共用同一個水塔、同一套電線**。搬進去只要把魔法搬家箱打開就好，一下午就搞定，一棟樓可以住幾十戶。

> 這就是 **VM 和 container 的差別**：VM 是獨棟房子，每台都有自己的作業系統 kernel（自己的水塔），很獨立但又大又慢；container 是公寓裡的一間房，共用主機的 kernel（大樓水塔），又小又快，一台機器能跑很多個。

---

## 大家用的都是同一個水塔

小晴住進公寓後，跑去敲隔壁的門。隔壁住的是小傑，他的房間佈置成海盜船，跟小晴的粉紅房間完全不一樣。

小晴問：「你家的水是從哪裡來的？」

小傑說：「頂樓那個藍色水塔啊。」

小晴愣住了：「我家也是！」

兩間房看起來天差地遠，但打開水龍頭，流出來的是**同一個水塔的水**。

而且小晴發現，她的房間門口貼著一張紙：「本戶最多用電 500 度、用水 3 噸」。就算她想開十台電扇，也不會把整棟樓的電用光。

> 這就是 **共用 kernel**：Alpine container 和 Ubuntu container 看起來不一樣（房間佈置不同），但 `uname -r` 印出來的是同一個 kernel（同一個水塔）。房間門鎖讓你看不到別人家，叫做 **namespaces**；門口的用電限額叫做 **cgroups**。所以 container 其實就是「被隔離、被限額的普通 process」。

---

## 如果你住的地方沒有水塔呢？

小晴的表哥住在另一個國家，那裡的大樓**用的是完全不同的水管規格**，小晴的魔法搬家箱接不上去。

表哥的爸爸想了一招：在家裡客廳先蓋一個**小小的透明溫室**，溫室裡裝了一個迷你水塔，規格跟小晴那邊一模一樣。這樣魔法搬家箱就能在溫室裡打開了。

表哥說：「好神奇！我還以為搬家箱是直接開在我家客廳的。」

> 這就是 **Windows／macOS 上的 Docker Desktop**：Linux container 需要 Linux kernel，Windows 和 macOS 沒有，所以 Docker Desktop 偷偷開了一台輕量 Linux VM（Windows 用 WSL2）。你的 container 其實是跑在那台 VM 裡。`docker version` 會看到 Client 是 `windows/amd64`，Server 卻是 `linux/amd64`。

---

## 搬家公司的四個人

魔法搬家箱不是自己會打開的。每次小晴要搬家，都有一個團隊在幫忙：

1. **櫃台小姐**：小晴只要跟她說「我要在 3 樓打開我的房間」，她就把這句話寫成一張工單。
2. **店長**：收到工單，負責所有大事——搬家箱放在哪個倉庫、房間要接哪條走廊、要不要先去總倉庫把箱子領回來。
3. **現場主管**：專門盯著每一間房從搬進來、住著、到搬走的整個過程。
4. **開箱師傅**：真正動手把箱子打開、裝好門鎖、貼上用電限額，弄好之後就把鑰匙交給小晴，自己先走了。

小晴從頭到尾只跟櫃台小姐講話，但其實後面有一整串人在幫忙。而且櫃台小姐不一定要在同一棟樓——她可以用電話把工單傳到別的城市的店長那裡。

> 這就是 **Docker 架構**：`docker` CLI（櫃台）把指令變成 API 請求，送給 `dockerd`（店長，管 image、網路、volume）；`dockerd` 交給 `containerd`（現場主管，管 container 生命週期）；最後 `runc`（開箱師傅）呼叫 kernel 建好 namespaces 和 cgroups，把你的 process 跑起來後就退場。CLI 和 daemon 是分開的，所以 CLI 可以連到遠端的 Docker 主機。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 「在我家明明睡得很好！」 | **「在我電腦可以跑」** 問題 |
| 寫給奶奶的長清單 | 安裝說明文件（每台機器照做一遍） |
| 魔法搬家箱 | **image**（打包好的環境） |
| 打開箱子、住進去的房間 | **container** |
| 院子裡蓋一棟獨棟小房子 | **VM**（有自己的 kernel） |
| 公寓裡的一間房 | **container**（共用主機 kernel） |
| 整棟樓共用的頂樓水塔 | **Linux kernel** |
| 房間的門鎖，看不到別人家 | **namespaces**（PID、網路、檔案系統隔離） |
| 門口的用電、用水限額 | **cgroups**（CPU、記憶體限制） |
| 客廳裡的透明溫室 | **Docker Desktop 的 Linux VM**（WSL2） |
| 櫃台小姐 | **`docker` CLI** |
| 店長 | **`dockerd`**（Docker daemon） |
| 現場主管 | **`containerd`** |
| 開箱師傅 | **`runc`** |
| 用電話把工單傳到別的城市 | CLI 透過 socket／named pipe 連到 daemon（也能連遠端） |

## 一句話記住

> **不要寫清單請別人照著買，直接帶著魔法搬家箱（image）走；打開來就是你的房間（container），住在公寓裡和大家共用同一個水塔（kernel），所以又小又快。**
