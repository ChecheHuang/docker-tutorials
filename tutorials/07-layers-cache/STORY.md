# 故事版：阿嬤的千層蛋糕店 🍰

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「千層蛋糕店怎麼做得又快又好」的故事，幫你「感覺」出 layer、build cache、快取失效、指令順序、`docker history` 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 一層一層疊上去

巷口的「阿嬤千層蛋糕店」每天早上都要做一個招牌千層蛋糕。

做法很固定，從下往上疊：

1. 最底下一片厚厚的餅乾底
2. 一層奶油
3. 一層草莓果醬
4. 最上面寫上今天的日期和祝福的話

每一層都要等前一層放好才能疊上去。疊好之後，下面的層就被壓住、不能再動了。

> 這就是 **layer**：image 是一層一層疊起來的，Dockerfile 每個 `RUN`、`COPY` 就是一層，疊上去之後是唯讀的。

---

## 冰箱裡的「半成品」

阿嬤的孫子小凱來幫忙。他發現阿嬤有個聰明的習慣：每做好一層，就**順手多做一份放進冰箱**，上面貼紙條寫「這是餅乾底＋奶油，跟昨天一樣」。

第二天早上，阿嬤打開冰箱一看：「餅乾底一樣、奶油一樣、果醬也一樣……」直接拿出冰箱裡那份做好三層的半成品，只要在最上面寫今天的祝福話就好。

本來要做一小時的蛋糕，五分鐘就好了。

> 這就是 **build cache**：同樣的步驟以前做過，就直接沿用結果。`docker build` 輸出裡的 `CACHED` 就是「從冰箱拿出來」。

---

## 中間換一層，上面全部重來

有一天，客人說：「我想要藍莓果醬，不要草莓。」

阿嬤打開冰箱：「餅乾底，一樣，拿出來。奶油，一樣，拿出來。果醬……不一樣了。」

問題來了：果醬在第 3 層，祝福話在第 4 層。**果醬換了，祝福話也得重寫** —— 因為字是寫在果醬上面的，底下換了，上面一定要重做。

但餅乾底和奶油不用動，它們在果醬**下面**。

> 這就是 **快取失效的連鎖規則**：某一層變了，它和它**上面**的所有層都要重做；下面的層照樣沿用。

---

## 小凱的大發現

小凱做了一陣子，發現一件奇怪的事：

阿嬤以前的做法是**先寫祝福話的紙條，夾在第二層**，然後才放果醬、放水果。

可是祝福話**每天都不一樣**！所以每天一到第二層就「跟昨天不一樣」，第二層以上通通要重做，冰箱裡的半成品幾乎沒用過。

小凱說：「阿嬤，祝福話每天都換，要放**最上面**才對。餅乾底幾個月才換一次配方，放最下面。」

阿嬤照著改：最少變的放最下面，最常變的放最上面。從此每天只要重做最上面那一層。

> 這就是 **指令順序**：先 `COPY go.mod go.sum` + `RUN go mod download`（幾個月才變一次的依賴），再 `COPY . .`（每天都在改的程式碼）。順序對了，快取才用得上。

---

## 一樣的字，不一樣的水果

有一陣子，阿嬤的食譜上寫著：「第 3 層：去市場買**今天最新鮮**的水果。」

奇怪的是，每天做出來的水果都是**第一天買的那一批**。

原來冰箱的規則是：「**食譜上的字**跟昨天一樣，就拿冰箱裡的。」它只看字，不會真的跑去市場確認今天有沒有新水果。食譜那行字從來沒改過，所以冰箱裡那份半成品就一直被拿出來用。

小凱只好在食譜上把「買水果」和「切水果放上去」寫在**同一行**，要換水果時就改那一行，讓冰箱知道「這次不一樣」。

> 這就是 **`RUN` 只比字串、不比結果** 的陷阱：`RUN apt-get update` 單獨一行會被快取住，永遠是舊的套件清單。要跟 `apt-get install` 寫在同一個 `RUN` 裡；真的想全部重來就用 `--no-cache`。

---

## 摸一摸不算換

有天小凱不小心碰了一下冰箱裡的奶油盒，緊張地問：「這樣奶油還能用嗎？」

阿嬤笑著說：「你只是摸了一下盒子，裡面的奶油又沒換，當然能用。」

> 這就是 **`COPY` 看的是內容**：檔案內容變了才失效，只是 `touch` 改時間不算。

---

## 挖掉一層，蛋糕不會變輕

有客人嫌蛋糕太重。小凱想了一個辦法：在最上面再疊一層「把下面的奶油挖掉」的步驟。

結果蛋糕一樣重。因為奶油還在下面那層裡，只是上面貼了一張「這裡當作沒有奶油」的紙。

> 這就是 **layer 只會往上加**：後面的 `RUN rm` 不會讓 image 變小，檔案還在下面那層。想真的變輕要換做法 —— 第 08 章的 multi-stage。

---

## 蛋糕側面的標籤

阿嬤在每個蛋糕盒側面貼了一張標籤，從上往下寫：

```
第 4 層  祝福話    今天早上做的
第 3 層  藍莓果醬  三天前做的（冰箱拿的）
第 2 層  奶油      上個月做的（冰箱拿的）
第 1 層  餅乾底    上個月做的（冰箱拿的）
```

客人看標籤就知道每一層是什麼、多重、什麼時候做的。

> 這就是 **`docker history`**：列出 image 的每一層，是哪個指令做的、多大、什麼時候做的。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 千層蛋糕的每一層 | **layer** |
| 疊好之後下面不能動 | layer 是**唯讀**的 |
| 冰箱裡的半成品 | **build cache** |
| 從冰箱拿出來用 | 輸出裡的 **`CACHED`** |
| 果醬換了，祝福話也要重寫 | 一層失效，**上面全部重做** |
| 餅乾底放最下面 | `COPY go.mod go.sum` + `go mod download` 放前面 |
| 祝福話放最上面 | `COPY . .` + `go build` 放後面 |
| 冰箱只看食譜上的字 | `RUN` 只比**指令字串** |
| 永遠是第一天的水果 | `RUN apt-get update` 被快取住 |
| 摸一下盒子不算換 | `COPY` 看內容，`touch` 不會失效 |
| 挖掉奶油，蛋糕一樣重 | 後面的 `RUN rm` 不會讓 image 變小 |
| 蛋糕盒側面的標籤 | **`docker history`** |
| 「今天全部重做」 | **`--no-cache`** |

## 一句話記住

> **image 是千層蛋糕，冰箱會留著做過的每一層；中間換一層，上面全部重做，所以最少變的（依賴）放最下面，最常變的（程式碼）放最上面。**
