# 故事版：夏令營的置物櫃 🎒

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「參加夏令營、每天換一間教室」的故事，幫你「感覺」出 container 可寫層、named volume、匿名 volume、bind mount、tmpfs、備份與還原 volume 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 每天都是全新的教室

小綠參加了一個為期十天的夏令營。營隊的規矩很特別：**每天早上，大家都會被分到一間全新布置好的教室**。教室裡的桌椅、海報、白板，每天都一模一樣，是照著同一張布置圖擺的。

第一天，小綠在教室白板上寫下他的**集點紀錄**：「完成游泳 ✓、完成攀岩 ✓」。

下課時，他先去吃午餐，回來白板上的字還在。「太好了！」

可是第二天早上，大家換到新的教室。小綠衝到白板前——**一片空白**。昨天的教室已經整間拆掉了。

> 這就是 **container 的可寫層**：image 是布置圖（唯讀），container 是照著布置出來的教室。你寫的東西都在白板上：`docker stop` 再 `start`（去吃午餐再回來）還在，`docker rm`（教室拆掉）就沒了。

---

## 有名字的置物櫃

輔導員看小綠哭喪著臉，帶他去走廊：「看，這裡有一整排**置物櫃**。你可以申請一個，門上**貼你的名字**。」

小綠申請了一個，門上寫著「小綠的集點本」。從此他把集點紀錄寫在**本子**上，放進置物櫃。

每天換教室時，輔導員會在新教室的書桌下，**接一條通道到小綠的置物櫃**。小綠一打開抽屜，就是他的集點本。教室拆了十次，本子一直都在。

> 這就是 **named volume**：`docker volume create shorty-db` 申請一個有名字的櫃子，`-v shorty-db:/var/lib/postgresql/data` 把它接到 container 裡的某個抽屜。container 刪了重建，只要接同一個名字，資料就還在。

---

## 沒寫名字的置物櫃

小綠的朋友阿紫比較迷糊，他沒去申請。可是營隊有一個貼心規則：「**數學教室**的這個抽屜一定要接置物櫃。如果你沒指定，我們就隨便幫你開一個，櫃門上貼一串亂碼。」

所以阿紫其實也有置物櫃——只是櫃門上寫著「7f3a9c…」。第二天換教室時，沒人知道那個亂碼櫃是阿紫的，新教室又隨便接了一個**新的**空櫃子。舊櫃子就孤零零留在走廊，裝著阿紫的作業。

營隊結束前，管理員清掉了一大堆亂碼櫃子。

> 這就是 **匿名 volume**：`postgres` image 宣告了 `VOLUME /var/lib/postgresql/data`，你沒掛東西時 Docker 自動建一個隨機名字的 volume。重建 container 不會自動接回去，舊的變成孤兒。`docker volume prune` 預設清的就是這些。

## 從家裡帶來的書包

到了美勞課，小綠想做一張海報，可是**素材都在家裡的書包**。

輔導員說：「沒問題，我們在你桌上開一個**傳送門**，直接通到你家的書包。」

小綠在家的媽媽把一張新的貼紙放進書包，教室裡的小綠**馬上**就在傳送門那頭看到了。小綠在教室剪了一張圖放進去，媽媽在家裡也看得到。

不過傳送門有兩個麻煩：

- 如果小綠家很遠（**另一個國家**），傳送門就很慢，一次搬一百張小貼紙要等好久。
- 書包是小綠家的，有些拉鍊只有家裡的人能拉；營隊的人想拉，常常被說「你沒有權限」。

> 這就是 **bind mount**：把 host 上**你指定的資料夾**直接接進 container，兩邊即時同步，開發時改 code 最方便。但在 Docker Desktop 上，`C:\` 的資料夾要跨 Windows ↔ Linux VM 的「國界」，大量小檔案會很慢；權限也跟著 host 走。資料庫請用置物櫃（named volume），不要用書包。

---

## 寫在起霧的窗戶上

下午下了一場雨，教室窗戶起霧了。小綠用手指在玻璃上算數學，算完就擦掉。

「為什麼不寫在本子上？」阿紫問。

「這些只是草稿，不用留下來，而且我不想讓別人翻到。寫在霧上最快，下課太陽一出來就自己消失了。」

> 這就是 **tmpfs**：放在記憶體裡的暫存空間，很快，container 一停就消失，不會寫到磁碟上。適合暫存檔，或是根本不想落地的東西。

---

## 影印一份，放到別的地方

營隊最後一天，輔導員說：「置物櫃明天要大掃除。想留紀念的，**影印一份**帶回家。」

小綠拿著集點本去影印機，可是輔導員攔住他：「等一下，你**先把筆放下**。你一邊寫一邊印，印出來會有半個字。」小綠停下來，影印了一份完整的。

另一個比較聰明的方法是：請**負責記錄的老師**直接幫他「抄一份清單」——老師邊上課邊抄也不會出錯，因為他知道哪些字已經寫完了。

回家後，小綠把影本放進**家裡的新抽屜**，然後真的打開來看了一次：「嗯，游泳 ✓、攀岩 ✓，全部都在。」

媽媽說：「對，**沒打開檢查過的影本，不能算數**。」

> 這就是 **備份與還原 volume**：開一個臨時 container 把 volume 打包成 `.tgz`（影印），打包前先 `docker stop db`（先把筆放下）；資料庫更推薦用 `pg_dump`（請老師抄清單，不用停機）。還原到一個**新的** volume，再開一個臨時 Postgres 讀讀看——驗證過的備份才算備份。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 布置圖 | **image**（唯讀 layer） |
| 照圖布置出來的教室 | **container** |
| 教室白板 | container 的**可寫層** |
| 去吃午餐再回來，白板還在 | `docker stop` / `start` 不會丟資料 |
| 教室整間拆掉 | `docker rm` |
| 門上貼名字的置物櫃 | **named volume**（`shorty-db`） |
| 接到書桌抽屜的通道 | `-v shorty-db:/var/lib/postgresql/data` |
| 貼亂碼的置物櫃 | **匿名 volume**（image 的 `VOLUME` 指令自動建的） |
| 清掉一堆亂碼櫃 | `docker volume prune` |
| 通到家裡書包的傳送門 | **bind mount** |
| 家太遠，傳送很慢 | Docker Desktop 上 `C:\` bind mount 的效能問題 |
| 拉鍊沒權限 | bind mount 的 uid/gid 權限問題 |
| 寫在起霧的窗戶 | **tmpfs** |
| 先把筆放下再影印 | 備份前先 `docker stop db` |
| 影印集點本 | 用臨時 container `tar` 打包 volume |
| 請老師抄清單 | **`pg_dump`** 邏輯備份 |
| 影本放進家裡的新抽屜 | 還原到新的 volume |
| 打開影本檢查 | 開臨時 Postgres 驗證還原結果 |

---

## 一句話記住

> **白板會跟教室一起拆掉（可寫層），重要的東西放在貼名字的置物櫃（named volume），影印過、打開檢查過的才算備份。**
