# 故事版：麵包店的標籤與冷凍倉庫 🥐

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「麵包店把麵包分批冷凍、貼標籤、送去倉庫」的故事，幫你「感覺」出 image tag、semver、git sha、`latest` 的陷阱、digest、OCI label、registry（Docker Hub／GHCR）、login／push／pull、imagetools inspect、`/version` 驗證是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 「今天的」到底是哪一天的？

阿嬤的麵包店做了一款很受歡迎的**蔥花麵包**。生意好到店裡做不完，阿嬤決定：每天做好的麵包先冷凍，送到**冷凍倉庫**，各家分店再去倉庫拿。

一開始，箱子上只貼一張標籤：「**最新的蔥花麵包**」。

結果某天，東區分店說麵包好鹹，西區分店說很正常。阿嬤去看——兩家分店的箱子都寫著「最新的蔥花麵包」。可是東區是**今天**拿的，西區是**上禮拜**拿的。「最新」這張貼紙，每天都被貼到新的箱子上。

沒人說得出來，鹹的那批到底是哪一天做的。

> 這就是**只靠 `latest` 的問題**：`latest` 不是「最新」的保證，只是「最後一個被貼上這個名字的」。兩台機器都說自己跑 `latest`，實際上可能是不同版本。

---

## 一箱貼好幾張標籤

阿嬤的孫子小凱想了一個辦法：每一箱貼**好幾張**標籤。

- 「**第 1 代 第 2 款 第 0 次修改**」：這張永遠不換，以後要找這批，看這張就對了。
- 「**第 1 代 第 2 款**」：同一款如果之後小修改（少放一點鹽），這張會移到新的箱子上。
- 「**第 1 代**」：只要還是第 1 代的配方，這張就跟著最新那箱走。
- 「**麵團編號 a1b2c3d**」：記錄是用哪一盆麵團做的，直接對得回廚房的紀錄本。
- 「**最新的**」：還是保留，給只是想嚐嚐看的客人用。

分店訂貨時，小凱規定一定要寫**不會換的那張**：「請給我第 1 代第 2 款第 0 次修改。」

> 這就是 **tag 策略**：同一個 image 打 `1.2.0`、`1.2`、`1`、`sha-a1b2c3d`、`latest` 好幾個 tag。semver 的 `1.2.0` 和 git sha 是不可變的，部署要用它們；`1.2`、`1`、`latest` 會移動。試作品（`1.3.0-rc.1`）不能搶走「第 1 代」和「最新的」那幾張。

## 標籤可以撕，指紋撕不掉

有一天小凱發現一件可怕的事：有位店員不小心把「第 1 代第 2 款第 0 次修改」**撕下來，貼到另一箱**上了。標籤是紙做的，誰都可以撕、可以貼。

阿嬤說：「那就再加一樣東西——**麵包的指紋**。」

倉庫有一台機器，會把整箱麵包的重量、形狀、成分全部量過一遍，算出一串長長的號碼。只要裡面有一顆麵包不一樣，號碼就會完全不同。這串號碼**不是人取的**，是麵包自己「長」出來的，所以沒辦法偷換。

> 這就是 **digest**：`sha256:` 開頭的一長串，是 image 內容算出來的雜湊。tag 可以被重新 push 覆蓋，digest 永遠只對應同一份內容。最穩的寫法是 `ghcr.io/chechehuang/shorty:1.2.0@sha256:...`，tag 給人看，digest 給機器驗證。

## 箱子側面的自我介紹貼紙

倉庫的人每天要處理幾百箱，常常搞不清楚：「這箱是誰家的？什麼時候做的？配方在哪裡可以查？」

所以全國的麵包店公會訂了一個**統一格式的自我介紹貼紙**，每一格都有固定的名字：

- **出處**：阿嬤麵包店，地址在哪裡
- **版本**：第 1 代第 2 款第 0 次修改
- **麵團編號**：a1b2c3d…
- **做好的時間**：2026 年 10 月 28 日早上 8 點
- **名字**：蔥花麵包

因為格式統一，倉庫、檢查員、分店的機器都看得懂，不用一家一家學。

> 這就是 **OCI label**：`org.opencontainers.image.source`、`version`、`revision`、`created`、`title` 這些標準 key。GHCR 會看 `source` 把 package 連到 GitHub repo；掃描工具和儀表板也會讀它們。label 不佔空間，用 `docker image inspect` 就看得到。

## 兩間冷凍倉庫

城裡有兩間大倉庫：

- **城市大倉庫**：最老牌，全城的人都知道去那裡拿東西。但是如果你沒有會員卡，每天能進去拿的次數有限制。
- **學校旁邊的倉庫**：就在阿嬤上課的烹飪學校旁邊。學校的人本來就有學生證，直接刷學生證就能進去放東西，不用另外辦卡。

阿嬤的配方筆記本就放在烹飪學校，所以她選了學校旁邊的倉庫。

要放東西進倉庫之前，要先**刷卡登入**；然後在箱子上寫清楚「**哪間倉庫／哪家店／什麼麵包：哪個版本**」。地址寫錯，倉庫管理員會直接說：「你沒有權限放東西到這裡。」

> 這就是 **registry**：Docker Hub（城市大倉庫，未登入有 pull 次數限制）和 GHCR（`ghcr.io`，跟 GitHub 帳號和 `GITHUB_TOKEN` 整合）。`docker login` 是刷卡，`docker tag` 是在箱子上寫完整地址，`docker push` 是放進倉庫，`docker pull` 是拿出來。名字沒寫 registry 就推，會被 `denied` 擋下來；GHCR 的名字還必須**全部小寫**。

---

## 不用搬出來，也能看箱子裡有什麼

分店店長想知道倉庫裡「第 1 代第 2 款」現在對到哪一箱，但不想把整箱搬回店裡。

倉庫有一個**查詢窗口**：報上名字，窗口就告訴你這張標籤現在貼在哪一箱、那箱的指紋是多少、裡面分成幾小包。

> 這就是 **`docker buildx imagetools inspect`**：直接問 registry，不用先 pull，就能看到 tag 對到的 digest 和 manifest。第 23 章多平台 image 時，它還會列出每個平台各自的那一份。

## 打開袋子，裡面還有一張小卡

最後，小凱在**每一顆麵包的袋子裡**都放一張小卡，上面寫著版本。

這樣就算箱子上的標籤被撕掉、被貼錯，分店只要打開一個袋子看小卡，就知道手上這顆麵包到底是哪一版。

而且小卡和箱子上的標籤，是**同一個時間、照同一張訂單**寫的，所以一定對得上。

> 這就是 **`/version` 驗證**：版本號在 build 時用 `-ldflags "-X main.version=${VERSION}"` 注入執行檔，跟 tag、label 用同一個 `VERSION` build arg。部署完 `curl localhost:8080/version`，回 `{"version":"1.2.0"}` 才算真的確認。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 冷凍的一箱麵包 | **image** |
| 「最新的」標籤 | **`latest`** tag（會移動） |
| 第 1 代第 2 款第 0 次修改 | **semver tag** `1.2.0`（不可變） |
| 第 1 代第 2 款、第 1 代 | `1.2`、`1`（會移動） |
| 麵團編號 | **git sha tag** `sha-a1b2c3d` |
| 試作品不搶標籤 | 預發佈版不更新 `latest` |
| 撕不掉的麵包指紋 | **digest** `sha256:...` |
| 統一格式的自我介紹貼紙 | **OCI label** `org.opencontainers.image.*` |
| 城市大倉庫 | **Docker Hub** |
| 學校旁的倉庫 | **GHCR** `ghcr.io` |
| 刷卡、學生證 | `docker login`、PAT／`GITHUB_TOKEN` |
| 箱子上寫完整地址 | `docker tag ghcr.io/<owner>/shorty:1.2.0` |
| 放進倉庫／拿出來 | `docker push`／`docker pull` |
| 倉庫的查詢窗口 | `docker buildx imagetools inspect` |
| 袋子裡的版本小卡 | `GET /version` |

## 一句話記住

> **一箱麵包要貼好幾張標籤（1.2.0、sha、latest），訂貨只寫不會換的那張，再用撕不掉的指紋（digest）確認，最後打開袋子看小卡（/version）——這才知道你拿到的是哪一批。**
