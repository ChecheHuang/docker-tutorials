# 故事版：博物館的夜班機器人 🤖

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「博物館替晚上值班的機器人做安全設定」的故事，幫你「感覺」出 non-root USER、read_only 與 tmpfs、no-new-privileges、cap drop、精簡 image、Trivy／Docker Scout 掃描、pin digest 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 舊機器人「大胖」

星光市立博物館晚上沒有人，所以館長買了一台夜班機器人，取名叫「大胖」。

大胖什麼都有：脖子上掛著**全館的萬能鑰匙**，腰上掛著梯子、電鑽、撬棍、無線電，肚子裡還貼著一張紙條，寫著保險箱的密碼——「這樣它遇到什麼狀況都能處理！」館長很得意。

某天晚上，一個小偷用一根磁鐵就把大胖「騙」了過去。小偷接著發現：萬能鑰匙在它脖子上、撬棍在它腰上、保險箱密碼在它肚子裡。

整座博物館，一夜被搬空。

> 這就是本章的 **`Dockerfile.bad`**：用 root 跑（萬能鑰匙）、裝了 curl 和 vim（撬棍和電鑽）、秘密寫在 `ENV`（肚子裡的紙條）。服務本身只要有一個漏洞，攻擊者就能拿到所有東西。

---

## 新機器人只拿一把小鑰匙

館長痛定思痛，請來安全顧問阿蘭。阿蘭的第一句話是：

「機器人的工作只是**在大廳巡邏、看到怪事就按鈴**。它根本不需要開金庫的鑰匙。」

新機器人「小青」只拿到一把**大廳的小鑰匙**。就算哪天小青也被騙了，小偷拿到的也只是一把開大廳門的鑰匙，金庫還是鎖得好好的。

> 這就是 **non-root `USER`**：`USER nonroot:nonroot`（uid 65532）。container 預設用 root 跑，而 container 裡的 root 跟主機上的 root 是同一個身分號碼，風險很大。shorty 只需要聽 8080 port，用普通使用者就夠了。

---

## 展示櫃全部上玻璃，只留一個小抽屜

阿蘭第二步，把大廳所有展示櫃都**蓋上鎖死的玻璃**。小青可以看、可以巡邏，但不能把任何東西放進展示櫃，也不能把展品換掉。

「那小青要記筆記怎麼辦？」館長問。

阿蘭在小青身上裝了一個**小抽屜**：可以放便條紙，但抽屜很小，而且每天早上關機時，抽屜裡的東西就會自動清空。

> 這就是 **`read_only: true` 加 tmpfs**：container 的檔案系統全部唯讀，攻擊者沒辦法寫入後門。真的需要寫的地方（像 `/tmp`）用 `tmpfs` 掛一塊記憶體空間，container 停掉就消失。shorty 只把 log 寫到 stdout，連抽屜都用不到。

---

## 徽章只能比現在小，不能變大

博物館裡有一種「**變身徽章**」：任何人別上它，就會暫時變成館長，可以打開所有的門。這是給緊急狀況用的。

阿蘭在小青身上加了一條規則：「**不管你撿到什麼徽章，你的權力永遠不能比現在更大。**」

就算小偷把變身徽章別在小青身上，小青也還是那個只有大廳鑰匙的小青。

> 這就是 **`no-new-privileges`**：`security_opt: [no-new-privileges:true]`。Linux 有一種「setuid 程式」，執行時會暫時變成檔案主人（常常是 root）。開了這個選項，process 和它生出來的子 process，都不能再取得更高的權限。

---

## 工具腰帶：先全部拿掉，缺什麼再加

大胖的腰帶上掛了二十幾種工具。阿蘭把小青的腰帶**全部清空**，然後問：「巡邏真的需要哪一樣？」

「手電筒。」館長想了想。

「好，那就只掛手電筒。」

電鑽、撬棍、可以假裝成館長聲音的無線電……全部不帶。小青就算想做壞事，手上也沒工具。

> 這就是 **`--cap-drop ALL`**：root 的權力被 Linux 拆成幾十個小能力（capability），例如改檔案主人、送偽造的網路封包。Docker 預設給一小組，我們乾脆**全部丟掉**，缺什麼再 `--cap-add` 加回來。shorty 一個都不需要。

---

## 機器人身上越少零件越好

阿蘭還做了一件事：把小青身上**用不到的零件全部拆掉**。

大胖有喇叭、投影機、印表機、一整套維修工具箱——每多一個零件，就多一個可能壞掉、可能被人動手腳的地方。小青只留下輪子、眼睛和警鈴。

「它甚至沒有手可以拿東西？」館長驚訝。

「對，」阿蘭說，「小偷就算控制了它，也沒辦法叫它去拿螺絲起子。」

> 這就是 **精簡 image**：shorty 的 runtime 用 `distroless/static`，裡面**沒有 shell、沒有 curl、沒有套件管理器**，只有憑證、時區資料和 shorty 本身。攻擊者找不到 `sh` 可以下指令，也找不到下載工具。

---

## 每週一次：拿零件清單對照「壞零件公告」

全國的機器人工廠會一起維護一張「**壞零件公告**」：哪一批螺絲容易斷、哪一款電池會過熱。

每個星期一，博物館的檢查員都會拿小青的**零件清單**，一個一個對照公告。對到了就標紅色：「這顆電池有問題，而且工廠已經出了新版，請換掉！」

有兩位檢查員輪流來，一位叫小崔，一位叫小史。他們用的公告版本有一點點不一樣，所以偶爾會一個說有問題、一個說沒有——這很正常，兩個都看一看比較放心。

> 這就是 **Trivy 和 Docker Scout 掃描**：讀出 image 裡所有套件，對照漏洞資料庫（CVE）。重點是 **HIGH／CRITICAL 而且有修正版**的要處理。而且公告每週都會更新，所以要**定期**掃，最好放進 CI（第 24 章）。

---

## 零件要認指紋，不只認名字

有一次，工廠寄來一箱「**標準輪子 第 12 款**」。可是這一箱跟上個月那箱看起來不太一樣——原來工廠悄悄改了設計，名字卻沒改。

阿蘭從此規定：訂零件時不只寫名字，還要寫上那一箱的**指紋號碼**。指紋號碼是根據零件本身算出來的，只要零件有一點點不同，號碼就完全不同。送來的箱子指紋對不上，就退貨。

「那以後有更好的新輪子怎麼辦？」

「有個小助手會定期來問：『新的第 12 款出了，指紋是這個，要換嗎？』我們檢查過，再改訂單上的號碼。」

> 這就是 **pin base image digest**：`FROM gcr.io/distroless/static-debian12:nonroot@sha256:...`。tag（名字）會移動，digest（指紋）永遠指向同一份內容。更新 digest 交給 Dependabot／Renovate 開 PR，人看過再合併。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 舊機器人大胖 | `Dockerfile.bad`（root、`golang:latest`、多裝工具、秘密在 ENV） |
| 萬能鑰匙 | 用 root（uid 0）執行 |
| 只拿大廳的小鑰匙 | **`USER nonroot:nonroot`** |
| 肚子裡的密碼紙條 | 寫死在 `ENV` 的秘密，`docker history` 看得到 |
| 展示櫃鎖上玻璃 | **`read_only: true`** |
| 關機就清空的小抽屜 | **tmpfs**（`--tmpfs /tmp`） |
| 權力不能比現在更大 | **`no-new-privileges`** |
| 變身徽章 | setuid 程式 |
| 清空工具腰帶 | **`--cap-drop ALL`** |
| 只把手電筒掛回去 | `--cap-add` 需要的那一個 |
| 拆掉用不到的零件 | **精簡 image**：distroless／scratch，沒有 shell |
| 壞零件公告 | **CVE 漏洞資料庫** |
| 檢查員小崔、小史 | **Trivy**、**Docker Scout** |
| 每週一檢查 | 定期掃描、放進 CI |
| 零件的指紋號碼 | **image digest**（`sha256:...`） |
| 來問要不要換新輪子的小助手 | Dependabot／Renovate |

## 一句話記住

> **安全的 container 就像夜班機器人：只給小鑰匙、櫃子上玻璃、權力不准變大、工具先全拿掉、零件越少越好，再每週對照壞零件公告、認指紋收貨。**
