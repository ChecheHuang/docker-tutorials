# 故事版：美術比賽的作品箱 🎨

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「把作品交給美術老師參加比賽」的故事，幫你「感覺」出 build context、`.dockerignore`、`ARG`、`ENV`、`--build-arg`、`-ldflags -X` 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 老師只看箱子裡的東西

學校要辦美術比賽。規則很特別：每個同學要把**一個箱子**交給美術老師，老師會在美術教室裡，照著你寫的製作步驟，用箱子裡的材料幫你把作品組好。

老師說：「我只會用**箱子裡的東西**。箱子外面的，就算你說『在我家書桌上』，我也拿不到。」

小樂的製作步驟寫在一張紙上，那張紙不用放進箱子，夾在外面交給老師就可以。

> 這就是 **build context**：`docker build` 最後那個 `app`，就是交給老師的箱子。`COPY` 只能從箱子裡拿，`COPY ../xxx` 拿不到箱子外的東西。製作步驟（Dockerfile）可以放在箱子外面，用 `-f` 告訴老師在哪。

---

## 把整個抽屜倒進箱子

小樂很懶，直接把**整個書桌抽屜**倒進箱子：彩色筆、黏土、膠水……還有一本日記、一張寫著家裡 Wi-Fi 密碼的小紙條、一疊練習時畫壞的草稿、去年比賽的獎狀。

箱子重得要命，老師打開要翻好久才找到材料。更糟的是，老師說：「你的作品步驟寫『把箱子裡**全部**的東西貼到畫板上』，所以你的 Wi-Fi 密碼也被貼上去，掛在走廊給大家看了。」

> 這就是 **context 裡混進不該有的東西**：`.git`、本機編好的執行檔、寫著密碼的 `.env`，都可能被 `COPY . .` 帶進 image。

---

## 「不要放進箱子」清單

媽媽幫小樂在箱子蓋子內側貼了一張清單：

```
不要放進去：
- 日記本
- 寫著密碼的紙條
- 練習用的草稿
- 說明書和閱讀心得
- 製作步驟紙本身
```

以後每次打包，只要照著清單，把這些東西挑出來，剩下的才放進箱子。

小樂問：「為什麼連製作步驟紙都不要放？老師不是要看嗎？」

媽媽說：「老師本來就會另外拿你的步驟紙。如果你把它也放進箱子，每次你改一個字，箱子裡的東西就『變了』，老師就要整箱重新檢查一遍。」

> 這就是 **`.dockerignore`**：放在 context 根目錄（`app/.dockerignore`），列出不要送進去的東西。shorty 的清單排除了 `.git`、`*_test.go`、`*.exe`、`*.md`、`Dockerfile`、`.dockerignore`、`.env`。排除 Dockerfile 是為了改 Dockerfile 時，`COPY . .` 的快取不會失效。

---

## 清單只管寫到的東西

有一次，小樂在抽屜裡放了一張漫畫。清單上沒有寫「漫畫」，所以漫畫就被放進箱子了。

還有一次，小樂的密碼紙條被塞在**鉛筆盒裡面**。清單上寫的是「抽屜裡的密碼紙條」，媽媽只檢查了抽屜最上層，沒有打開鉛筆盒，紙條又溜進去了。

媽媽只好把清單改成：「**不管藏在哪一層**的密碼紙條都不要放。」

> 這就是 **`.dockerignore` 是黑名單**：沒寫到的都會進去。而且 `*.md` 只比對根目錄，要排除每一層都要寫 `**/*.md`。

---

## 這是第幾版？

比賽前，小樂改了好幾次作品。老師把作品掛上走廊之後，小樂跑去看，卻認不出：「這是我第三版還是第五版？」

作品背面什麼都沒寫。

下一次，小樂在交箱子時附了一張小便條：「**這次是第 5 版**。」老師照著步驟組作品時，用印章在作品背面蓋上「第 5 版」。

從此每件作品掛出來，翻過來一看就知道是哪一版。

> 這就是 **`--build-arg VERSION=v0.1.0`** + **`-ldflags "-X main.version=${VERSION}"`**：build 時帶一個版本號進去，蓋在執行檔裡面。shorty 跑起來後，`GET /version` 就會回答 `{"version":"v0.1.0"}`。

---

## 便條和說明卡不一樣

小樂發現，老師處理兩種紙的方式不一樣：

- **小便條**（「這次是第 5 版」）：老師在**製作的時候**看，用完就丟進回收桶。作品掛出來後，便條已經不在了。
- **說明卡**（「作品名稱：海底城市」）：老師會**貼在作品旁邊**，作品掛多久它就跟多久，經過的人都看得到。

如果小樂想讓走廊上的人也看到版本，就要請老師「把便條上的字，抄到說明卡上」。

> 這就是 **`ARG` vs `ENV`**：`ARG` 只活在 build 期間（便條），`ENV` 會一直留在 image 和 container 裡（說明卡）。要接力就寫 `ARG VERSION` 再 `ENV APP_VERSION=$VERSION`。

---

## 便條不要太早給

有一次，小樂一開始就把「第 6 版」的便條交給老師。結果老師說：「便條換了，我得從**第一步**開始重做 —— 因為我每一步都會先看一下便條。」

本來材料準備、打底這些步驟上次都做過了，只因為便條換了，全部重來。

後來小樂學乖了：把便條**放在最後一步之前**才給。前面那些打底的步驟沒看到便條，就可以直接沿用上次的。

> 這就是 **ARG 的快取規則**：`ARG` 之後的每個 `RUN` 都會受它影響。所以 `ARG VERSION` 要放在 `go mod download` 之後，換版本號才不會連依賴都重新下載。

---

## 便條上不要寫秘密

小樂的哥哥說：「我有一個參賽密碼，寫在便條上給老師就好了吧？反正便條用完就丟。」

老師搖搖頭：「我每次製作都會**留一份工作紀錄**，上面抄著我看過的每一張便條。誰來翻紀錄都看得到。」

> 這就是 **ARG 和 ENV 都不能放秘密**：`docker history`、`docker inspect` 都看得到。秘密要用第 11 章的 secret mount 和第 14 章的做法。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 交給老師的箱子 | **build context**（`app/`） |
| 老師只用箱子裡的東西 | `COPY` 只能從 context 拿 |
| 夾在外面的步驟紙 | Dockerfile，用 **`-f`** 指定 |
| 整個抽屜倒進去 | context 混進 `.git`、`.env`、執行檔 |
| 密碼被貼在走廊上 | 秘密被 `COPY . .` 帶進 image |
| 蓋子內側的「不要放」清單 | **`.dockerignore`** |
| 連步驟紙都不放進箱子 | 排除 `Dockerfile`，改它不會讓 `COPY . .` 失效 |
| 沒寫到的漫畫跑進去 | `.dockerignore` 是**黑名單** |
| 藏在鉛筆盒裡的紙條 | `*.md` 只比對根目錄，要用 `**/` |
| 「這次是第 5 版」的便條 | **`--build-arg VERSION=...`** |
| 在作品背面蓋版本章 | **`-ldflags "-X main.version=..."`** |
| 翻過來看版本 | **`GET /version`** |
| 用完就丟的便條 | **`ARG`**（只活在 build 期間） |
| 貼在作品旁的說明卡 | **`ENV`**（container 執行時還在） |
| 便條太早給，全部重做 | `ARG` 放太前面，依賴層快取失效 |
| 老師的工作紀錄 | `docker history`，所以秘密不能放 ARG |

---

## 一句話記住

> **老師只看箱子裡的東西：用清單（`.dockerignore`）把日記和密碼挑出來，用便條（`ARG`）告訴老師這是第幾版、蓋在作品背面（`-ldflags -X`），而且便條最後才給、上面不寫秘密。**
