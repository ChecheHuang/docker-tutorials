# 故事版：巷口早餐店的開店清單 🥪

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「巷口早餐店每天早上開店」的故事，幫你「感覺」出多服務 compose、用名字互相呼叫、`depends_on` 加 `service_healthy`、healthcheck、named volume、`.env` 變數替換和 `.env.example` 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 一個人開不了早餐店

阿珠阿姨開了一家早餐店。一開始她只賣烤吐司，一個人就忙得過來，可是有個問題：**她什麼都記在腦子裡**，晚上一睡覺，今天誰點了什麼、誰還欠錢，隔天全忘光了。

後來店裡多了兩位幫手：

- **豆漿機大叔**：負責煮豆漿，還會把每一筆訂單**寫在一本厚厚的帳本**上。
- **保溫櫃小妹**：把常常有人點的蛋餅先做好放著，客人一點就能馬上拿，不用每次重煎。

阿珠阿姨在牆上貼了一張**開店清單**，三個人的工作都寫在同一張紙上。

> 這就是**多服務的 compose**：`app`（shorty）、`db`（Postgres）、`cache`（Redis）寫在同一個 `compose.yaml`。只有 shorty 時是 in-memory，重啟就忘光；有了 Postgres 才記得住。

---

## 喊名字就好

第一天，阿珠阿姨要問豆漿機大叔一件事，她對著空氣喊：「**我自己**，豆漿好了沒？」

當然沒人回答——她在問她自己。

保溫櫃小妹笑著說：「阿姨，妳要喊『**豆漿機**』啊！」

從此店裡的規矩是：**要找誰，就喊誰的名字**。喊「豆漿機」，豆漿機大叔就會回應；喊「保溫櫃」，保溫櫃小妹就會回應。這個名字只在**店裡面**有用，在外面的馬路上喊，沒有人知道你在叫誰。

而且大叔和小妹都在**廚房裡面**工作，沒有開窗口給路上的客人。只有阿珠阿姨站在**前面的櫃台**，客人從那裡點餐。

> 這就是 **compose 預設網路的 DNS**：service 名稱就是主機名稱，`DATABASE_URL` 寫 `@db:5432`、`REDIS_URL` 寫 `cache:6379`。在 container 裡寫 `localhost` 是指自己。`db`、`cache` 沒寫 `ports`，只有 `app` 開了 `8080:8080` 給外面。

---

## 豆漿機要先熱好

開店第一天就出包了。

阿珠阿姨一到店裡就把鐵門拉起來開始收單。第一個客人點了豆漿，她喊：「豆漿機！一杯豆漿！」

豆漿機大叔說：「等一下啦，我**才剛插電**，豆子還沒磨、水還沒滾！」

客人等不及就走了。

第二天，阿珠阿姨學乖了。她在開店清單上寫：

> 阿珠阿姨：要等**豆漿機的綠燈亮**、**保溫櫃的綠燈亮**，才能拉開鐵門。

豆漿機上有一顆小燈，大叔每隔五秒看一下：豆漿煮好了，就把燈切成綠色。保溫櫃也一樣，小妹會問自己：「準備好了嗎？」回答「好了！」，燈就變綠。

光是「大叔**人已經到店裡了**」還不夠，要等**綠燈**。

> 這就是 **`depends_on` + `condition: service_healthy`**：只寫 `depends_on: [db]` 只會等 container **啟動**（大叔人到了），`service_healthy` 才會等 **healthcheck 通過**（綠燈亮）。豆漿機的燈是 `pg_isready`，保溫櫃的燈是 `redis-cli ping`，「每隔五秒看一下」是 `interval: 5s`。

### 阿珠阿姨自己也會再問一次

就算等到綠燈，阿珠阿姨開門後還是會先喊一聲：「豆漿機，你真的好了吧？」沒回應就等一秒再問，最多問十次。

因為有些日子，她會去別的分店幫忙——**那裡沒有人幫她看綠燈**。

不過她對保溫櫃就沒這麼有耐心：喊一次沒回應，她就氣得直接回家不開店了。所以保溫櫃的綠燈，對她來說特別重要。

> 這就是 **depends_on + 程式內重試的雙保險**：shorty 連 Postgres 會重試 10 次，因為 K8s 之類的環境沒有 `depends_on`；但連 Redis 沒有重試，連不上就 `fatal`，所以 `cache` 的 `service_healthy` 是必要的。

---

## 帳本放在抽屜裡

每天晚上打烊，三個人會把店收乾淨：桌子擦好、機器關掉、人都回家。

但豆漿機大叔的**帳本**不會丟掉，它放在店裡一個**有名字的抽屜**裡，抽屜上貼著「帳本」兩個字。隔天早上大叔一來，打開抽屜，昨天的帳都還在。

只有一種情況帳本會不見：阿珠阿姨說「**連抽屜一起清空！**」那就真的什麼都沒了，大叔得從一本新帳本開始寫。

> 這就是 **named volume**：`db-data:/var/lib/postgresql/data`，頂層 `volumes:` 宣告抽屜、service 底下說要用哪個抽屜。`docker compose down` 打烊但抽屜還在；`docker compose down -v` 才是連抽屜一起清空。

---

## 黑板上的填空

店裡有一個**暗號**，送貨的叔叔要說對暗號，大叔才會開後門讓他進來。

阿珠阿姨在開店清單上這樣寫：

> 後門暗號：＿＿＿＿（**如果沒填，就用「早安」**）

真正的暗號，她寫在一張小紙條上，**放在開店清單旁邊的小盒子裡**。每天早上大家讀清單時，看到空格就去小盒子找紙條，把暗號填進去。紙條沒有的話，就用「早安」。

她還在牆上貼了一張**範本紙條**，上面寫著：「後門暗號＝改成你自己的」，讓新來的幫手知道小盒子裡應該放什麼。範本可以給大家看，**真正的紙條絕對不貼出來**。

> 這就是 **`.env` 變數替換**：`${POSTGRES_PASSWORD:-shorty}`，Compose 讀檔時從 shell 環境變數或 **compose 檔旁邊的 `.env`** 找值，沒有就用 `:-` 後面的預設值。**`.env.example`** 是範本，進版控；`.env` 放真正的值，列在 `.gitignore`。

### 換了暗號，大叔卻不認

有一天阿珠阿姨把紙條上的暗號改成「午安」。結果送貨叔叔說「午安」，大叔卻不開門。

原來大叔在**第一天**就把暗號抄進了自己的帳本，之後只看帳本，不再看紙條。要改暗號，得請大叔自己在帳本上改，或是整本帳本重來。

> 這就是 **`POSTGRES_PASSWORD` 只在第一次初始化有效**：volume 裡已經有資料，postgres 就不會再讀這個變數。改了 `.env` 密碼卻連不上，第 20 章會教怎麼處理。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 早餐店的三個人 | 三個 **service**：`app`、`db`、`cache` |
| 牆上同一張開店清單 | 同一個 **`compose.yaml`** |
| 阿姨什麼都記在腦子裡 | shorty 的 **in-memory** store |
| 豆漿機大叔和他的帳本 | **Postgres** |
| 先做好放著的蛋餅 | **Redis 快取** |
| 喊「豆漿機」而不是「我自己」 | **service 名稱 DNS**（`db`，不是 `localhost`） |
| 名字只在店裡有用 | compose 的 **`<project>_default` 網路** |
| 只有櫃台對外 | 只有 `app` 有 **ports**，`db`、`cache` 沒有 |
| 大叔人到了 | `service_started` |
| 綠燈亮了 | **`service_healthy`** |
| 每隔五秒看一下燈 | **healthcheck** `interval: 5s` |
| 豆漿機的燈、保溫櫃的燈 | `pg_isready`、`redis-cli ping` |
| 阿姨自己再問十次 | shorty 連 Postgres 的**重試迴圈** |
| 對保溫櫃只問一次 | shorty 連 Redis **沒有重試** |
| 貼著「帳本」的抽屜 | **named volume** `db-data` |
| 打烊、抽屜還在 | `docker compose down` |
| 連抽屜一起清空 | `docker compose down -v` |
| 清單上的填空「沒填就用早安」 | `${POSTGRES_PASSWORD:-shorty}` |
| 清單旁小盒子裡的紙條 | **`.env`**（不進版控） |
| 牆上的範本紙條 | **`.env.example`**（進版控） |
| 大叔只看第一天抄的暗號 | `POSTGRES_PASSWORD` 只在**第一次初始化**生效 |

---

## 一句話記住

> **一張清單寫三個人；找人喊名字不喊自己（service DNS）；等綠燈才開門（service_healthy）；帳本收在有名字的抽屜（named volume）；暗號寫在小盒子的紙條上（.env），牆上只貼範本（.env.example）。**
