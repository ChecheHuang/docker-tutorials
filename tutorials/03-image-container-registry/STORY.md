# 故事版：小芸家麵包店的餅乾模具 🍪

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「麵包店用餅乾模具壓餅乾」的故事，幫你「感覺」出 image 和 container 的差別、registry／repository／tag／digest 是什麼、`pull`、`images`、`rmi` 在做什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 一個模具，壓出好多片餅乾

小芸家開麵包店，最受歡迎的是**小熊餅乾**。

做法很簡單：櫃子裡有一個**鐵做的小熊模具**，把麵糰鋪平，模具往下一壓，就是一片小熊餅乾。壓一百次，就有一百片。

小芸拿了一片餅乾，用巧克力筆幫小熊畫了一副眼鏡。旁邊另一片是弟弟的，他給小熊畫了鬍子。

兩片餅乾都是從同一個模具壓出來的，可是一片有眼鏡、一片有鬍子，**互不影響**。

而且最重要的是：**模具本身完全沒有被畫到**。下一片壓出來的小熊，還是乾乾淨淨、沒眼鏡也沒鬍子。

> 這就是 **image 和 container**：image 是模具，**唯讀**、不會被改；container 是壓出來的餅乾，每一片有自己可以畫的表面（**可寫層**）。同一個 image 可以跑出很多個 container，各自的變更互不影響，也不會寫回 image。用 `docker diff` 可以看到「這片餅乾被畫了什麼」。

---

## 吃掉餅乾，眼鏡就沒了

小芸好喜歡她畫的眼鏡小熊，可是放了一下午，被弟弟偷吃掉了。

她哭著說：「我的眼鏡小熊不見了！」

媽媽說：「再壓一片就好啦。」

可是新壓出來的小熊，**當然沒有眼鏡**——眼鏡是畫在被吃掉的那片上，不是畫在模具上。

媽媽說：「如果你希望**每一片**小熊都有眼鏡，要去改**模具**，不是改餅乾。」

> 這就是 **container 刪掉，變更就消失**：在 container 裡改的檔案，`docker rm` 之後就不見了，新的 container 一樣是乾淨的。想讓每個 container 都有這個改變，要改 image（改 Dockerfile 重新 build，第 06 章）；想保存資料，要放到 volume（第 13 章）。

---

## 模具中心：好大好大的倉庫

小芸家的模具不是自己做的，是從城裡的**模具中心**買來的。

模具中心是一棟好大的建築，裡面有好多**架子**：一個架子專門放小熊模具，一個架子放星星模具，一個放愛心模具。

同一個架子上又有很多版本：小熊**一號**、小熊**二號**、小熊**戴帽子版**……每一個模具都**貼著一張標籤**。

小芸跟櫃台說：「我要小熊架子上，標籤寫『戴帽子版』的那個。」櫃台就把那個模具拿給她。

除了城裡這間最大的，也有別的模具中心，例如隔壁鎮的模具中心，或是某家大公司自己開的模具中心。

> 這就是 **registry、repository、tag**：registry 是模具中心（Docker Hub、GHCR……），repository 是一個架子（`nginx`、`redis`），tag 是模具上的標籤（`1.27-alpine`、`latest`）。完整的名字像 `docker.io/library/nginx:1.27-alpine`：哪個中心、哪個區、哪個架子、哪張標籤。沒寫中心就是預設的 Docker Hub，沒寫標籤就是 `latest`。

---

## 標籤會被換，指紋不會

有一天，小芸照樣跟模具中心說：「我要小熊架子上貼著『**最新**』標籤的那個。」

拿回家一壓，咦？小熊的耳朵變圓了，跟上個月的不一樣！

原來，模具中心上禮拜做了一個新版小熊，就把「最新」那張標籤**撕下來，貼到新模具上**了。

小芸的爸爸說：「標籤是貼紙，隨時可以撕掉換位置。如果你要**一模一樣**的那個模具，要看它**底部刻的指紋號碼**。」

每個模具底部都刻了一串很長的號碼，是照著模具的形狀算出來的。形狀只要差一點點，號碼就完全不同。所以只要說出這串號碼，拿到的保證是同一個模具。

> 這就是 **tag 和 digest**：tag（標籤）可以被移動，`latest` 不代表最新，也不保證今天和明天一樣；digest（`sha256:...`，刻在底部的指紋）是內容算出來的，同一個 digest 永遠是同一份內容。`docker images --digests` 可以看到，`docker pull nginx@sha256:...` 可以指定指紋拉。

---

## 一張標籤，貼兩個名字

小芸想給她最愛的模具取一個自己的名字，叫「**芸芸小熊**」。

她沒有去買新模具，只是在原本的模具上**多貼一張標籤**。現在這一個模具身上有兩張標籤：「戴帽子版」和「芸芸小熊」。

後來她不喜歡這個名字了，把「芸芸小熊」那張撕掉——模具還在，因為還有「戴帽子版」那張標籤。

> 這就是 **`docker tag`** 和 **`docker rmi` 的 Untagged**：`docker tag alpine:3.22 my-alpine:test` 只是多貼一張標籤，IMAGE ID 一樣。`docker rmi my-alpine:test` 只會 `Untagged`，要等最後一張標籤也撕掉，才會真的 `Deleted`。

---

## 有餅乾在用的模具不能丟

櫃子太擠了，媽媽想把小熊模具丟掉。

小芸大喊：「不行！烤箱裡還有三片小熊餅乾在烤！」

麵包店的規矩是：**只要還有用這個模具做的餅乾在店裡（就算是放涼了、還沒賣掉的），就不能把模具丟掉**。要先把那些餅乾處理掉，才能丟模具。

> 這就是 **`docker rmi` 的 conflict 錯誤**：`unable to delete ... container ... is using its referenced image`。只要還有 container（就算已經停了）是從這個 image 跑出來的，就不能直接刪。先 `docker ps -a` 找出來、`docker rm`，再 `docker rmi`。

---

## 先看看自己家有哪些模具

小芸每次要去模具中心前，都會先打開自家的櫃子看一看：有哪些模具、各貼了什麼標籤、多大多重。

如果櫃子裡**已經有**那個模具，就不用再跑一趟模具中心了。而且很多模具共用一樣的**底座**，底座家裡已經有一個，就只要買上面那一截。

> 這就是 **`docker images`** 和 **`docker pull`**：`docker images` 列出本機的 image；`docker pull` 從 registry 下載，已經有的 layer 會顯示 `Already exists`，不用重新下載。本機已經有的 image，`docker run` 會直接用，不會自動去拉新的。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 鐵做的小熊模具 | **image**（唯讀模板） |
| 壓出來的餅乾 | **container**（執行中的實例） |
| 在餅乾上畫的眼鏡 | container 的**可寫層**（`docker diff` 看得到） |
| 餅乾被吃掉，眼鏡也沒了 | `docker rm` 後變更消失 |
| 要每片都有眼鏡就要改模具 | 改 **Dockerfile** 重新 build |
| 城裡的模具中心 | **registry**（Docker Hub、GHCR） |
| 一個放小熊模具的架子 | **repository**（`nginx`、`redis`） |
| 模具上的標籤 | **tag**（`1.27-alpine`、`latest`） |
| 「最新」標籤被撕下來貼到新模具 | **`latest` 會移動** |
| 模具底部刻的指紋號碼 | **digest**（`sha256:...`） |
| 多貼一張「芸芸小熊」標籤 | **`docker tag`** |
| 撕掉一張標籤，模具還在 | `docker rmi` → **Untagged** |
| 有餅乾在店裡就不能丟模具 | `rmi` 的 **conflict** 錯誤 |
| 打開自家櫃子看看 | **`docker images`** |
| 從模具中心買回來 | **`docker pull`** |
| 共用的底座家裡已經有 | 共用 **layer**：`Already exists` |

---

## 一句話記住

> **模具（image）不會被畫到，壓出來的餅乾（container）各自畫各自的；模具從模具中心（registry）的架子（repository）上拿，標籤（tag）會被換，底部的指紋（digest）不會。**
