# 故事版：給機器人廚師的餅乾步驟卡 🍪

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「寫步驟卡給機器人廚師烤餅乾」的故事，幫你「感覺」出 Dockerfile、`FROM`、`WORKDIR`、`COPY`、`RUN`、`CMD`、`EXPOSE`、build context 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 奶奶的餅乾，只有奶奶會做

小芸的奶奶會烤全世界最好吃的巧克力餅乾。班上同學吃過一次，每個人都想要。

可是奶奶每次做的步驟都不太一樣：今天先放糖，明天先放蛋；有時候烤十二分鐘，有時候「看起來差不多了」就拿出來。小芸跟著做了三次，三次味道都不一樣。

「奶奶，你到底怎麼做的？」

「就……憑感覺啊。」

> 這就是**手動做環境的問題**：進到機器裡一個指令一個指令打，做出來的東西沒人能照樣再做一次。

---

## 鎮上的機器人廚師

鎮上新開了一間「機器人廚房」。裡面的機器人廚師很厲害，但有個怪脾氣：**它只看步驟卡，卡上沒寫的事，它一件都不做**。

小芸決定把奶奶的做法寫成一張卡片，一行一個步驟：

```
1. 從「一整間烘焙教室」開始
2. 走到 3 號工作桌
3. 把我帶來的材料籃，整籃倒在桌上
4. 揉麵糰、放進烤箱烤
5. 貼一張「從右邊小窗口拿」的貼紙
6. 有人打開盒子時：端出餅乾
```

機器人照著卡片做，做完之後把整個成果**封進一個禮盒**。不管誰拿這張卡片、拿同一籃材料去機器人廚房，做出來的禮盒都一模一樣。

> 這就是 **Dockerfile**：把「怎麼做出這個 image」一行一行寫下來的步驟卡。機器人廚師是 **`docker build`**，封好的禮盒是 **image**。

---

## 每一行在做什麼

小芸跟機器人一起，一行一行看。

**「從一整間烘焙教室開始」**——機器人不會憑空變出烤箱和麵粉，總要有個起點。小芸選了一間設備最齊全的教室，裡面有烤箱、攪拌機、量杯，什麼都有。

> 這就是 **`FROM`**：選一個現成的 image 當起點。我們選的是 `golang:1.26`，裡面有完整的 Go 工具。

**「走到 3 號工作桌」**——教室很大，總要說清楚在哪張桌子做事，不然材料會被倒在地上。說了一次，之後的步驟都在這張桌子上做。

> 這就是 **`WORKDIR`**：之後的指令都在這個資料夾裡執行，資料夾不存在會自動準備好。

**「把材料籃整籃倒在桌上」**——小芸帶來的那一籃，裡面有麵粉、巧克力、還有奶奶的祕密配方紙條。

> 這就是 **`COPY . .`**：把你交出去的東西，複製進 image 裡。

**「揉麵糰、放進烤箱」**——真正動手做事的步驟。這一步只在**做禮盒的時候**做一次。

> 這就是 **`RUN`**：在 build 的時候執行指令，例如 `go build` 把程式編出來。

**「貼一張從右邊小窗口拿的貼紙」**——貼紙只是告訴大家「餅乾從這裡拿」。貼紙本身不會把窗口打開，要真的拿，還得有人去把窗戶推開。

> 這就是 **`EXPOSE`**：只是說明服務用哪個 port，真正對外開門要靠 `docker run -p`。

**「有人打開盒子時：端出餅乾」**——這一步不是現在做，是**以後每次有人打開禮盒**時才做。

> 這就是 **`CMD`**：container 啟動時要執行的事。`RUN` 是做菜，`CMD` 是上菜。

---

## 不小心把「開店」寫成「做菜」

第一次寫卡片的時候，小芸寫錯了一行：

```
4. 揉麵糰、放進烤箱烤，然後站在門口一直發餅乾
```

機器人很聽話，烤完就站在門口發餅乾……發了一整個下午，一直沒有回來封盒子。禮盒永遠做不完。

小芸這才搞懂：「做的時候」和「打開的時候」是兩件事，要分開寫。

> 這就是 **`RUN` 和 `CMD` 搞混**：把啟動伺服器寫成 `RUN`，build 會卡住永遠不結束。

---

## 材料籃要交對

第二次，小芸匆匆忙忙，把**整個房間的雜物**都拖去機器人廚房：書包、玩具、跳繩……真正的材料籃反而被埋在裡面的某個角落。

機器人照卡片「把籃子倒在桌上」，結果桌上全是玩具，找不到麵粉在哪，只好停下來說：「找不到配方紙條。」

> 這就是 **build context**：`docker build` 最後那個參數，決定你把哪一籃東西交給機器人。shorty 要交的是 `app/` 這一籃，交錯了就會出現 `go.mod file not found`。步驟卡可以放在別的地方（`-f`），但材料一定要從這一籃拿。

---

## 禮盒怎麼這麼重？

禮盒做好了，打開真的是奶奶的味道！小芸好開心，抱著禮盒要拿去學校——

「怎麼這麼重？」

打開一看：裡面除了餅乾，還有**整間烘焙教室**。烤箱、攪拌機、量杯、剩下的麵粉、奶奶的配方紙條，全都被一起封進去了。因為卡片第一行就寫了「從一整間烘焙教室開始」，機器人就把整間教室當成盒子的一部分。

餅乾只有一小盤，盒子卻有一台冰箱那麼大。

> 這就是 **shorty 第一版 image 有 ~1GB** 的原因：`FROM golang` 把整套 Go 工具、原始碼、下載的依賴都留在 image 裡，真正需要的只有一個 ~18MB 的執行檔。第 07、08 章會慢慢把盒子變小。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 奶奶「憑感覺」做餅乾 | 手動進 container 打指令，無法重現 |
| 寫給機器人的步驟卡 | **Dockerfile** |
| 機器人廚師照卡片做 | **`docker build`** |
| 封好的禮盒 | **image** |
| 打開禮盒、端出餅乾 | **container** 啟動 |
| 從一整間烘焙教室開始 | **`FROM golang:1.26`** |
| 走到 3 號工作桌 | **`WORKDIR /src`** |
| 把材料籃倒在桌上 | **`COPY . .`** |
| 揉麵糰、烤餅乾 | **`RUN go build`**（build 時做一次） |
| 「從右邊小窗口拿」的貼紙 | **`EXPOSE 8080`**（只是說明） |
| 打開盒子時端出餅乾 | **`CMD ["shorty"]`**（每次啟動都做） |
| 站在門口發餅乾、盒子封不起來 | 把啟動伺服器寫成 `RUN`，build 卡住 |
| 交給機器人的那一籃 | **build context**（`app/`） |
| 拖了整個房間的雜物去 | context 給錯（`.` 而不是 `app`） |
| 連整間教室都封進盒子 | image **~1GB** |

---

## 一句話記住

> **Dockerfile 是給機器人廚師的步驟卡：`FROM` 選教室、`WORKDIR` 選桌子、`COPY` 倒材料、`RUN` 動手做、`CMD` 是打開盒子才做的事；第一版能吃，但連整間教室都封進盒子裡了。**
