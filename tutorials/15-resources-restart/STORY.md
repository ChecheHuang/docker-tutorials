# 故事版：開心農場的圍欄與鬧鐘 🐐

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「農場裡每隻動物都有自己的圍欄」的故事，幫你「感覺」出記憶體限制、CPU 限制、OOM killed（exit 137）、Go 的 `GOMEMLIMIT`、restart policy、`docker update` 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 沒有圍欄的農場

阿樂的爺爺有一座小農場，養了一隻**小山羊**、一隻**大乳牛**、一隻**小倉鼠**。

一開始，農場沒有任何圍欄，大家都在同一片草地上吃草。

某個夏天，小山羊突然胃口大開，從早吃到晚，把整片草地都吃光了。大乳牛餓到沒力氣擠牛奶，小倉鼠找不到瓜子。

更糟的是，爺爺急著要空出草地，**隨手抓了一隻動物趕出去**——結果抓到的是什麼都沒做錯的大乳牛。

> 這就是**沒有資源限制的 container**：大家共用整台機器的記憶體。一個有 memory leak，大家一起餓肚子；機器記憶體不夠時，kernel 挑誰殺掉不一定是兇手。

---

## 每隻動物都有自己的圍欄

爺爺決定幫每隻動物蓋**圍欄**：小山羊一小格、大乳牛一大格、小倉鼠一個籠子。圍欄裡的草就是那隻動物的份，吃完了也不能跑去吃別人的。

爺爺還發現，有些圍欄旁邊有一塊**後院**，草吃完了可以偷偷鑽過去吃後院的。「這樣圍欄就沒意義了！」他把後院的門也一起釘死。

> 這就是 **`--memory 128m`**（圍欄大小）和 **`--memory-swap 128m`**（把後院的門也釘死，不准用 swap）。只設 `--memory` 時，預設還能再用等量的 swap。

---

## 一聲不響被帶走

有一天，小山羊又暴食了。牠吃光了圍欄裡的草，還想繼續吃。

農場的規矩很嚴格：**超過圍欄的份量，管理員會直接把那隻動物帶走**，不會先警告、不會讓牠說話。

隔天爺爺走過去，圍欄裡空空的，只留下一張紙條：「**137 號：被管理員帶走，原因：吃太多**」。

阿樂問：「小山羊有沒有留下什麼話？」

爺爺搖頭：「被帶走的動物來不及說任何話。我們只能看紙條上的**號碼**和**原因**。」

> 這就是 **OOM killed**：container 超過記憶體上限，kernel 直接 `SIGKILL`，程式連 log 都來不及寫。exit code **137** = 128 + 9（SIGKILL）。要確認是不是吃太多，看 `docker inspect` 的 **`OOMKilled`**——因為 137 也可能是有人硬把它拉走的（`docker kill`）。

---

## 吃飯時間表

除了草，動物們還要輪流用**唯一的一台飲水機**。

爺爺規定：小倉鼠每一分鐘可以用飲水機**三十秒**。時間一到，就算還沒喝飽，也要先讓開，等下一分鐘。

小倉鼠平常喝水很快，三十秒綽綽有餘。可是夏天很熱的時候，牠要喝很久，就得一直排隊，喝得很慢。

> 這就是 **`--cpus 0.5`**：每 100ms 最多用 50ms 的 CPU 時間，用完就被暫停到下一輪（throttling）。平常沒感覺，尖峰時就會變慢。

## 聰明的小倉鼠

小倉鼠有個壞習慣：牠會把瓜子殼**全部塞在臉頰裡**，等臉頰塞到兩倍大才吐出來。

在沒有籠子的時候沒問題。可是現在籠子很小，牠常常臉頰還沒塞到「該吐」的程度，就已經**撐爆籠子**被管理員帶走了——明明一大半都是不要的殼！

阿樂在籠子上貼了一張小紙條：「**快塞到八分滿的時候，就先把殼吐掉。**」

小倉鼠看到紙條，從此快滿的時候就勤勞一點清殼，再也沒有被帶走過。

不過爺爺提醒：「這張紙條只管得了**殼**。如果小倉鼠真的吃下太多瓜子（不是殼），紙條也救不了牠。」

> 這就是 Go 的 **`GOMEMLIMIT`**：Go 的 GC 預設等 heap 長到兩倍才收垃圾（臉頰塞兩倍才吐），它**不知道**籠子多大。設 `GOMEMLIMIT=100MiB`（大約上限的 80～90%）告訴 runtime「快到了就先收垃圾」。但它是軟限制——真正存活的資料超過上限，還是會 OOM。

## 三種不同的鬧鐘

農場的動物偶爾會累倒、睡著。爺爺幫每個圍欄裝了不同的**鬧鐘**：

- **沒有鬧鐘**：倒下就一直躺著，等爺爺發現才會叫醒。
- **生病鬧鐘**：只有動物是**生病倒下**的才響，最多響三次。如果是正常睡飽了躺下，就不吵牠。
- **除非我說晚安鬧鐘**：不管怎麼倒下都會響、把動物叫起來。但如果是爺爺親口說「晚安，今天休息」，就不響——**連隔天農場重新開門時也不響**。
- **永遠鬧鐘**：不管怎麼倒下都叫起來。爺爺說晚安時當下不響，可是**隔天農場一開門，它照樣把動物叫醒**。

小山羊配的是「除非我說晚安」鬧鐘。結果有一陣子，牠每次被叫醒就去暴食、又被帶走、又被叫醒、又被帶走……紙條上的次數一直增加。

爺爺嘆氣：「**鬧鐘只會把牠叫起來，不會治好牠的暴食。**」

> 這就是 **restart policy**：`no`、`on-failure:3`、`unless-stopped`、`always`。差別在「exit code 是不是 0」和「Docker daemon 重啟時，你手動停掉的要不要叫起來」。OOM + restart 會變成重啟迴圈（`Restarting (137)`），`RestartCount` 一直增加——restart policy 不會修好問題。

## 不用拆圍欄就能挪

有一天爺爺發現，大乳牛的圍欄太小了。他本來以為要把整個圍欄拆掉重蓋，還得先把乳牛趕出去。

結果農場管理員說：「不用，圍欄可以**直接往外挪**。鬧鐘也可以直接換一個。」

「那我想順便把貼在籠子上的紙條改掉呢？」阿樂問。

「紙條是蓋圍欄時就貼好的，那個要拆掉重蓋才能改。」

> 這就是 **`docker update`**：不重建 container 就能改 `--memory`、`--cpus`、`--restart`。但環境變數（包括 `GOMEMLIMIT` 那張紙條）、port、volume 都是建立時決定的，要改只能重建。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 大家共用的一片草地 | 沒有限制時，container 共用整台機器的資源 |
| 隨手抓錯動物趕出去 | host 記憶體不足時，kernel 不一定殺到兇手 |
| 每隻動物的圍欄 | **`--memory`**（cgroup 記憶體上限） |
| 後院的門 | swap；**`--memory-swap`** 設成一樣 = 釘死 |
| 一聲不響被管理員帶走 | **OOM killed**（`SIGKILL`，沒有 log） |
| 紙條上的「137 號」 | **exit code 137** = 128 + 9 |
| 紙條上的「原因：吃太多」 | **`OOMKilled=true`** |
| 飲水機一分鐘只能用三十秒 | **`--cpus 0.5`**（CPU throttling） |
| 臉頰塞到兩倍才吐殼 | Go GC 預設 `GOGC=100` |
| 「快八分滿就先吐殼」紙條 | **`GOMEMLIMIT`** |
| 吃下太多瓜子（不是殼） | 真正的 memory leak，`GOMEMLIMIT` 救不了 |
| 沒有鬧鐘 | `--restart no` |
| 生病才響、最多三次 | `--restart on-failure:3` |
| 除非我說晚安 | `--restart unless-stopped` |
| 永遠鬧鐘 | `--restart always` |
| 隔天農場重新開門 | Docker daemon（或 Docker Desktop）重啟 |
| 一直被叫醒又被帶走 | OOM 重啟迴圈，`RestartCount` 增加 |
| 直接把圍欄往外挪 | **`docker update --memory`** |
| 蓋圍欄時貼的紙條 | 環境變數，要重建 container 才能改 |

---

## 一句話記住

> **每隻動物都要有圍欄（--memory），超過就被一聲不響帶走（137 + OOMKilled）；Go 要貼「快滿先清殼」紙條（GOMEMLIMIT），鬧鐘只會叫醒、不會治病（restart policy）。**
