# 故事版：麵包店的魔法儲藏櫃 🥐

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「麵包店每天早上做新麵包」的故事，幫你「感覺」出 BuildKit、`# syntax=`、cache mount、secret mount、buildx、`--progress=plain`、`builder prune` 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 每天早上都從零開始

小麥家開了一間麵包店。每天早上，爸爸都要做一批新的可頌送到便利商店。

做可頌的規矩很嚴格：**每一批都要在一張全新、乾淨的工作桌上做**，做完整張桌子連同麵包一起封起來送走。這樣每一批都一模一樣，客人吃起來不會一天鹹一天甜。

可是問題來了：工作桌是全新的，所以**麵粉、奶油、酵母**每天都要重新去市場買。就算昨天才剩半袋麵粉，也不能拿來用，因為那半袋已經跟著昨天的桌子封走了。

爸爸每天光是跑市場就要一個小時。

> 這就是**沒有 cache mount 的 build**：每一層都乾乾淨淨，可是只要那一層要重做，`go mod download` 就得把所有依賴重新下載一次。

---

## 新來的店長：一本會看食譜的筆記

有一天，店裡來了一位新店長，叫「小巴」。小巴做事比以前快很多：兩條不相干的生產線（揉麵團、熬果醬）他會**同時開工**，不用一條做完才做下一條。

小巴還有一個習慣：開工前，他會先看食譜**第一行**寫的小字——「請用第一版的看食譜方法」。他就去書架拿那一版的《看食譜說明書》，照著它讀懂整份食譜。

「這樣以後食譜多了新寫法，我只要換一本說明書，不用換掉整個店長。」小巴說。

> 這就是 **BuildKit**（新的 builder，會平行跑不相干的 stage）和 **`# syntax=docker/dockerfile:1`**（Dockerfile 第一行，指定用哪個版本的「前端」來解析 Dockerfile）。

---

## 魔法儲藏櫃

小巴在廚房角落放了一個**魔法儲藏櫃**。

這個櫃子很特別：它**不屬於任何一張工作桌**。做麵包的時候，櫃門打開，爸爸可以從裡面拿麵粉、奶油；做完之後，桌子封起來送走，**櫃子留在店裡**，剩下的材料還在。

隔天早上，爸爸打開櫃子：「哇，麵粉還有、奶油還有，只缺酵母！」他只要去市場買**酵母那一樣**就好。一小時的採買變成五分鐘。

最棒的是：因為櫃子沒有跟著麵包封走，**送出去的麵包盒也不會變重**。

不過小巴提醒：「每一個步驟要用材料，都要**自己打開櫃門**。你在『秤材料』那一步開了櫃子，『揉麵團』那一步沒開，揉麵團時就看不到櫃子裡的東西喔。」

> 這就是 **`RUN --mount=type=cache`**：給某個 `RUN` 一個跨 build 保留、但**不進 image** 的資料夾。shorty 掛了兩個：`/go/pkg/mod`（下載的模組，像麵粉奶油）和 `/root/.cache/go-build`（編譯好的半成品，像昨天先擀好的麵皮）。每個要用的 `RUN` 都要各自掛一次。

## 只借一下的倉庫鑰匙

有一天，便利商店說要做「特製巧克力可頌」，巧克力只有一間**上鎖的特約倉庫**才有。倉庫老闆給了爸爸一把鑰匙。

爸爸本來想把鑰匙**黏在工作桌上**，方便拿。小麥大叫：「不行！桌子做完要封起來送到便利商店，大家都會看到那把鑰匙，誰都能去倉庫偷巧克力！」

爸爸又想：「那我拿完巧克力，再把鑰匙從桌上撕下來就好？」小巴搖頭：「封桌子的時候每一步都會拍照存檔。你撕掉了，**前面那張照片裡鑰匙還在**。」

小巴的做法是：去倉庫的那**一趟**，他從口袋拿出鑰匙交給爸爸；爸爸一回來，鑰匙立刻**收回小巴的口袋**。桌子上、照片裡，從頭到尾都沒有鑰匙。

> 這就是 **`RUN --mount=type=secret`**：秘密（例如私有模組要用的 token、`.netrc`）只在**這一個 `RUN`** 期間出現，結束就消失，不進 layer、不進 `docker history`。build 時用 `--secret id=netrc,src=...` 交給 BuildKit。「每一步都拍照」就是 layer——`COPY` 進來再 `rm` 也沒用。

## 看清楚每一步：大聲報告模式

平常小巴做事很安靜，牆上的進度板只顯示「揉麵團 ✓」「烤箱 ✓」，做完的步驟就折起來。

有一天可頌烤焦了，爸爸想知道哪一步出問題。小巴說：「我切換成**大聲報告模式**。」接下來每一步，他都把細節一行一行唸出來：「第九步，秤麵粉，從儲藏櫃拿……用了 8 秒。」「第十一步，烤箱溫度……」

全部唸完，爸爸一下就找到：烤箱那一步多烤了三分鐘。

> 這就是 **`--progress=plain`**：把每一步的完整輸出都印出來，不折疊。除錯、看哪一步花最久、看有沒有 `CACHED`，都靠它。

## 另一間分店的廚房

麵包店生意越來越好，小巴說：「我可以在隔壁再開一間**獨立廚房**，那邊的設備更多，能同時做給不同國家的麵包。」

可是爸爸發現：新廚房有**自己的魔法儲藏櫃**，裡面是空的！第一次在新廚房做，又得全部去市場買。還有，新廚房做好的麵包，要記得**搬回總店的展示櫃**，不然客人看不到。

> 這就是 **`docker buildx`** 與 **builder**：`docker buildx create --driver docker-container` 會開一個獨立的 builder，快取跟預設 builder 分開；用它 build 要加 `--load` 才會回到 `docker images` 裡。多平台是第 23 章的事。

---

## 儲藏櫃塞爆了

一年後，魔法儲藏櫃塞滿了：過期的奶油、早就不做的抹茶粉、三年前的聖誕裝飾糖。

小巴拿出清單：「我先丟掉**沒有人在用**的東西。」櫃子空出一半。爸爸問：「那全部清掉呢？」小巴說：「可以，可是明天早上就要從頭去市場買喔。」

> 這就是 **`docker builder prune`**：清掉沒被使用的 build 快取。`--filter until=24h` 只清舊的，`-a` 全清（連 cache mount 一起），下一次 build 會從零開始。`docker system df` 的「Build Cache」那一行看得到櫃子有多滿。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 每一批都用全新工作桌 | 每個 layer 都是乾淨、可重現的 |
| 每天重新去市場買材料 | 沒有 cache mount 時，依賴整個重新下載 |
| 新店長小巴，會同時開兩條生產線 | **BuildKit**（平行跑 stage） |
| 食譜第一行「用第一版的看食譜方法」 | **`# syntax=docker/dockerfile:1`** |
| 不屬於任何桌子的魔法儲藏櫃 | **`RUN --mount=type=cache`** |
| 櫃子裡的麵粉奶油 | `/go/pkg/mod`（module 快取） |
| 昨天先擀好的麵皮 | `/root/.cache/go-build`（編譯快取） |
| 每一步都要自己開櫃門 | 每個 `RUN` 都要各自掛 cache mount |
| 黏在桌上的鑰匙 | 用 `ARG`／`COPY` 傳秘密（會留在 image 裡） |
| 撕掉了但照片裡還在 | `RUN rm` 刪不掉前一層的檔案 |
| 只借一趟、馬上收回的鑰匙 | **`RUN --mount=type=secret`** + `--secret` |
| 特約倉庫 | 私有 Go module（`GOPRIVATE` + `.netrc`） |
| 大聲報告模式 | **`--progress=plain`** |
| 隔壁的獨立廚房 | **`docker buildx create`** 建的 builder |
| 新廚房的空儲藏櫃 | 不同 builder 的快取是分開的 |
| 搬回總店展示櫃 | `--load` |
| 清理塞爆的儲藏櫃 | **`docker builder prune`** |

---

## 一句話記住

> **材料放魔法儲藏櫃（cache mount），明天還在、但不跟麵包一起送走；鑰匙只借一趟（secret mount），桌上照片裡都不能出現。**
