# 故事版：話劇社的演出單 🎭

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「學校話劇社準備演出」的故事，幫你「感覺」出 Docker Compose、`compose.yaml`、service、ports、environment、`up`／`down`／`ps`／`logs`、`--build` 和 project name 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 每次都要從頭交代一遍

小安是話劇社的社長。每次排練前，她都要站在舞台中間大聲交代：

「阿哲，你演國王，穿紅色斗篷，從左邊那扇門出場，記得講話要大聲，戴金色皇冠……」

光交代一個人就要講好久。更糟的是：

- 上禮拜交代過什麼，她自己也記不太清楚。
- 新加入的同學沒聽到，只能問東問西。
- 改一個小地方（例如斗篷換成藍色），又要把整串重講一次。

> 這就是**一長串 `docker run` 的問題**：`-p`、`-e`、`--name`、`--stop-timeout`……每次都要重打，指令只存在你的終端機歷史裡，新同事看不到。

---

## 把交代寫成一張演出單

老師給小安一個建議：「把要交代的事**寫在一張演出單上**，貼在後台。」

小安寫了這樣一張單子：

> **演出單**
> 角色：國王
> - 演員：阿哲（服裝間做好的紅斗篷版本）
> - 出場門：舞台左邊的門，對著觀眾席第一排
> - 隨身小紙條：「說話大聲」、「台詞速度：普通」

從此以後，排練前小安只要喊一聲：「**照演出單，開始！**」大家就各就各位。

> 這就是 **`compose.yaml`**：把「要跑哪些 container、每個怎麼設定」寫成一個檔案，放進版控。角色就是 **service**（`app`），出場門對著觀眾席是 **ports**（`"8080:8080"`），隨身小紙條是 **environment**（`LOG_LEVEL: info`）。喊「照演出單，開始！」就是 `docker compose up`。

### 演出單不用寫「第幾版格式」

舊的演出單最上面都會印一行「演出單格式 第 3.8 版」，其實根本沒人看。新的演出單把這行拿掉了，寫了反而會被老師提醒「這行不用寫喔」。

> 這就是**不要寫 `version:`**：Compose v2 已經不需要它，寫了只會出現 obsolete 警告。

---

## 照單子，不是照心情

有一次小安把「隨身小紙條」改成「台詞速度：很慢」，然後又喊了一次「照演出單！」

阿哲本來已經站在台上了。他看了看單子，發現**跟自己現在的樣子不一樣**，就先下台，換上新的小紙條，再重新上台。至於其他沒被改到的角色，**站在原地不動**。

> 這就是 **`up` 是宣告式的**：Compose 比對 compose 檔和現況，設定沒變的 container 不動，變了的就**重建**（`Recreated`）。改完檔案，再 `docker compose up -d` 一次就好。

---

## 斗篷要重做，得先說一聲

阿哲的紅斗篷是**服裝間**照圖紙做的。後來小安把圖紙改成「斗篷要加金邊」，然後喊「照演出單，開始！」

結果阿哲上台，穿的還是**舊的**紅斗篷，沒有金邊。

小安很生氣，服裝間的同學說：「妳只說『開始』，又沒說『**先把服裝重做一遍**』。架子上已經有一件紅斗篷了，我們就直接拿給他啊。」

從此小安都喊：「**先重做服裝，再開始！**」

> 這就是 **`docker compose up --build`**：有 `build:` 的 service，如果 image 已經存在，Compose 預設直接用舊的。改了程式碼要記得 `--build`。服裝間就是 **build context**（`../../app`），圖紙是 **Dockerfile**，做好掛在架子上、貼著「國王斗篷」標籤的是 `image: shorty:ch17`。

---

## 點名和看台詞紀錄

演出前，小安想知道大家是不是都到了。她看了一眼後台的**點名板**：

| 角色 | 狀態 | 出場門 |
|------|------|------|
| 國王 | 在台上，15 秒了 | 左門 → 第一排 |

> 這就是 **`docker compose ps`**：只列出這齣戲（這個 project）的 container 和狀態。

她也想知道剛剛台上講了什麼。話劇社有個錄音員，會把每個人講的話記下來，**每一句前面都寫上是誰講的**：

> 國王｜我宣布，從今天起……
> 國王｜來人啊！

角色多的時候，大家的台詞會交錯在一起，靠前面的名字就分得出來。

> 這就是 **`docker compose logs -f app`**：每行前面的 `app-1 |` 是 service 名稱 + 編號，多個服務的 log 交錯時靠它分辨。

---

## 收場：拆布景，但道具留著

演出結束，小安喊：「**收場！**」

大家下台、布景拆掉、舞台清空。可是服裝間架子上那件做好的斗篷**還掛著**，下次演出可以直接用。

如果只是中場休息，小安會喊：「**暫停！**」大家站在原地不動，布景也不拆，等一下喊「繼續」就能接著演。

> 這就是 **`docker compose down`**（刪除 container 和 network，但 image 留著）和 **`stop`／`start`**（只停住，container 還在）。

---

## 兩個班的布景撞在一起

學校的大禮堂很搶手。三年二班和三年五班剛好在同一天排練，兩班的演出單都有一個角色叫「國王」。

如果大家都只寫「國王」，後台就亂了：三年五班的老師喊「國王下台」，結果二班的國王也跟著下台。

所以禮堂規定：**每一班的東西都要貼班級名牌**。二班的國王叫「二班-國王-1號」，五班的國王叫「五班-國王-1號」，布景也貼「二班的舞台」、「五班的舞台」。

名牌如果沒特別寫，就用**演出單放在哪個班級櫃子**來決定。

可是不管名牌怎麼貼，**舞台左邊那扇門只有一扇**。二班的國王已經站在那扇門口，五班的國王就擠不進去。

> 這就是 **project name**：Compose 用它當前綴，container 叫 `17-compose-basics-app-1`、網路叫 `17-compose-basics_default`。沒指定時，取自 compose 檔所在的**資料夾名稱**，也可以用 `-p`、`COMPOSE_PROJECT_NAME` 或頂層 `name:` 指定。但 host 上的 port 只有一個，兩套都要 8080 就會 `port is already allocated`。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 每次站在台上大聲交代 | 一長串 `docker run` 參數 |
| 貼在後台的演出單 | **`compose.yaml`** |
| 演出單上的一個角色 | **service**（`app`） |
| 出場門對著觀眾席第一排 | **ports** `"8080:8080"` |
| 隨身小紙條 | **environment** |
| 「演出單格式第 3.8 版」那行 | 過時的 `version:`，不要寫 |
| 「照演出單，開始！」 | **`docker compose up -d`** |
| 只換被改到的人，其他人不動 | 宣告式：設定變了才 **Recreate** |
| 服裝間 | **build context**（`../../app`） |
| 斗篷圖紙 | **Dockerfile** |
| 架子上貼標籤的斗篷 | **image**（`shorty:ch17`） |
| 「先重做服裝，再開始！」 | **`up --build`** |
| 點名板 | **`docker compose ps`** |
| 錄音員記下「誰說了什麼」 | **`docker compose logs`**（`app-1 |` 前綴） |
| 「收場！」拆布景、斗篷留著 | **`down`**（image、volume 預設保留） |
| 「暫停！」／「繼續」 | **`stop`**／**`start`** |
| 班級名牌 | **project name**（`-p`、`name:`、資料夾名稱） |
| 舞台左門只有一扇 | host port 只有一個 → `port is already allocated` |

## 一句話記住

> **別每次站在台上從頭交代：把角色、出場門、小紙條寫成一張演出單（compose.yaml），喊一聲就開演（up），改了服裝圖紙記得先重做（--build），收場時布景拆掉、斗篷留著（down）。**
