# 故事版：公寓大樓的對講機 🏢

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「住在公寓大樓裡的三個好朋友要互相聯絡」的故事，幫你「感覺」出 network、bridge、container 裡的 `localhost`、內建 DNS、`-p` 埠對應（NAT）、`host` 模式、`host.docker.internal` 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 「打給我家」打到了自己家

小蝦、阿豆、米米是好朋友，搬進了同一棟公寓。小蝦開了一間**短網址小郵局**，阿豆負責**記帳本**（所有網址都記在他那裡），米米負責**便條紙**（常用的網址先抄一張，下次不用翻帳本）。

第一天，小蝦要問阿豆一筆帳，他拿起家裡的電話，按了「**打給我家**」。

電話響了——是他自己家的電話在響。

「咦？我要找阿豆啊！」

原來每一戶都有一個「打給我家」的按鈕，它永遠只會打回**按的那一戶自己**。小蝦按「我家」，當然打到小蝦家；阿豆的帳本在阿豆家，不在這裡。

> 這就是 **container 裡的 `localhost`**：每個 container 都有自己的網路，`localhost`（127.0.0.1）永遠指**自己**。shorty 連 `localhost:5432`，敲的是 shorty 自己的門，Postgres 不在那裡。

---

## 舊大樓：有門牌，沒有名冊

小蝦改成打阿豆的**房號**：「302」。通了！

可是過了幾天，阿豆搬到同一棟的另一間，房號變成「507」。小蝦又打不到了。他跑去管理室問：「阿豆住哪裡？」

管理員說：「我們這是**老大樓**，只有房號，**沒有住戶名冊**。你只能自己記號碼。」

> 這就是 **預設的 `bridge` network**：每個 container 都有 IP（房號），彼此可以連，但**沒有名字解析**。IP 會變，寫死 IP 很快就壞。

---

## 新大樓：對講機叫名字就好

三個好朋友決定一起搬到隔壁的**新大樓**。新大樓是他們自己跟管理公司申請蓋的，門口掛著「shorty 社區」。

新大樓的每一戶都有一台**對講機**，對講機接到管理室的**總機**。只要按下對講機說：「我要找**阿豆**。」總機就會查名冊，幫你接到阿豆現在住的那一戶——不管他搬到哪一間。

小蝦按對講機：「阿豆，幫我查一筆帳。」「米米，這張便條你有沒有？」通通一叫就到。

而且總機很聰明：如果你要找的不是社區住戶，例如「市政府」，它會幫你轉給外面的大總機。

> 這就是 **自訂 network + 內建 DNS**：`docker network create shorty-net` 蓋一棟新大樓；接在上面的 container，用**名字**（`--name db`、`--name cache`）就能互相找到。總機是 `127.0.0.11`。外面的網址（`go.dev`）它會轉給 host 的 DNS 查。

---

## 大門口的警衛：街上的人怎麼找進來

小郵局開張了，可是街上的客人看不到大樓裡面，只看得到**大樓的大門**和門上的號碼。

警衛伯伯說：「這樣吧，大門外面掛一個**8080 號信箱**。有人投信到 8080，我就幫你把信送到**小蝦家的 8080 號窗口**。」

客人只知道「大樓的 8080 號信箱」，根本不知道小蝦住幾樓幾號。這樣就夠了。

小蝦問：「那阿豆和米米要不要也掛一個信箱？」

警衛伯伯搖搖頭：「客人只需要找你啊。阿豆和米米是你在大樓**裡面**用對講機找的，不用對街上開信箱。掛了反而讓陌生人可以直接去翻帳本。」

> 這就是 **`-p 8080:8080`（NAT 埠對應）**：host 的 8080 轉到 container 的 8080。只有 shorty 需要 `-p`；db、cache 在 network 裡面互連就好，不要對外開 port。

---

## 窗口要開在正確的地方

有一天，警衛把信送到小蝦家門口，敲了半天沒人應。

原來小蝦的窗口開在**房間最裡面的小衣櫃裡**，只有他自己在家裡伸手才搆得到。從門口進來的信，根本送不到。

小蝦把窗口改開在**大門旁邊**，從此警衛送來的信都收得到了。

> 這就是 **程式要監聽 `0.0.0.0`，不能只聽 `127.0.0.1`**：從 `-p` 轉進來的連線是從「網卡」進來的，不是從 container 自己的 `localhost`。只聽 `127.0.0.1` 的程式，在 container 裡自己測得到，外面就是連不進來。

---

## 住在大廳的人

大樓裡有一位老爺爺不想住在任何一戶，他直接把床搬到**一樓大廳**。

好處是：客人一進大門就看到他，不用警衛轉信。壞處是：他沒有自己的門，什麼聲音都聽得到、誰都能直接走到他面前；而且大廳只有一個，兩個人想睡同一個角落就會吵架。

> 這就是 **`--network host`**：container 不隔離，直接用 host 的網路，`-p` 沒有意義、port 也可能跟 host 上的程式撞。在 Docker Desktop 上，「大廳」預設是那台 Linux VM 的大廳，不是你的 Windows 電腦。

---

## 打電話回老家

小蝦有時候要打電話給住在大樓**外面**的媽媽（你自己的電腦）。

他試著按「打給我家」，又打回自己房間了。總機告訴他：「要找大樓外面的房東家，請說**『房東家』**這個特別的名字。」

> 這就是 **`host.docker.internal`**：從 container 連回 host 上的服務。Docker Desktop 內建；Linux 上要加 `--add-host=host.docker.internal:host-gateway`。

---

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 每一戶自己的「打給我家」按鈕 | container 裡的 **`localhost`**（永遠指自己） |
| 小蝦的小郵局 | shorty |
| 阿豆的記帳本 | Postgres（`db`） |
| 米米的便條紙 | Redis（`cache`） |
| 房號 | container 的 **IP**（會變） |
| 只有房號、沒有名冊的老大樓 | 預設 **`bridge`** network（沒有 DNS） |
| 自己申請蓋的新大樓 | **`docker network create shorty-net`** |
| 對講機叫名字 | **內建 DNS**，用 container 名字互連 |
| 管理室總機 | `127.0.0.11` |
| 大門外的 8080 號信箱 + 警衛轉信 | **`-p 8080:8080`**（NAT） |
| 阿豆、米米不用掛信箱 | db、cache 不需要 `-p` |
| 窗口開在衣櫃裡 | 程式只聽 `127.0.0.1` |
| 窗口開在大門旁 | 程式聽 `0.0.0.0` |
| 睡在大廳的老爺爺 | **`--network host`** |
| 「房東家」這個特別名字 | **`host.docker.internal`** |

---

## 一句話記住

> **「我家」永遠是自己家（localhost）；同一棟新大樓用對講機叫名字（自訂 network + DNS），街上的客人只認大門信箱（-p）。**
