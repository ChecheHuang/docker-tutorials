# 故事版：到處跑的魔法點心車 🚚

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「同一台點心車開到不同城市擺攤」的故事，幫你「感覺」出 12-factor 設定、環境變數、`-e`／`--env-file`、為什麼秘密不能 bake 進 image、`docker history`、檔案掛載的秘密（`/run/secrets`、`_FILE`）是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 一台車，每天去不同的地方

小桃的爸爸有一台**魔法點心車**。這台車是工廠照著同一張設計圖做出來的，每一台都一模一樣：同樣的烤箱、同樣的冰箱、同樣的招牌。

星期一，車子開到海邊；星期三，開到學校門口；星期六，開到夜市。

每個地方都不一樣：海邊要賣冰的、學校要準備比較多零錢、夜市要開到很晚。

小桃問：「那我們要不要做三台車？一台海邊專用、一台學校專用、一台夜市專用？」

爸爸笑了：「不用。**車子只要一台**。每天出門前，我在駕駛座貼一張**今天的工作單**就好。」

> 這就是 **12-factor 的設定原則**：只 build **一個 image**，每個環境的差異（DB 在哪、log 等級）在**啟動時**從外面給。不要為每個環境各做一個 image。

---

## 工作單：一張一張貼，或一整本夾上去

工作單有兩種給法：

- 爸爸今天只想改一件事，就用**便利貼**：「今天營業到晚上十點」，貼在方向盤上。
- 要寫的很多時，媽媽會準備一個**資料夾**，裡面一頁一頁寫好：地點、營業時間、今天的特價品、要找誰收貨。爸爸整本夾在駕駛座旁邊。

便利貼跟資料夾寫的東西如果不一樣，爸爸會很困惑，所以媽媽規定：**同一件事只寫在一個地方**。

還有，資料夾的規矩很死板：寫「`營業時間=十點`」就是十點；如果寫「`營業時間="十點"`」，爸爸就真的會以為營業時間是「**引號十點引號**」。

> 這就是 **`-e KEY=VALUE`**（便利貼）和 **`--env-file shorty.env`**（資料夾）。`--env-file` 的格式很陽春：值原封不動，引號不會被拿掉，也不能寫註解在行尾。

## 不能漆在車身上的東西

點心車最有名的是**祕密醬汁**。醬汁的配方鎖在一個保險箱裡，保險箱的**密碼**只有爸爸知道。

有一天，新來的工讀生想偷懶：「每天都要記密碼好麻煩，我們乾脆把密碼**漆在車身側面**，這樣誰開車都知道！」

小桃大叫：「不行！車子每天開到街上，**所有人都看得到車身**！」

工讀生又說：「那我漆在車子**底盤**，漆完再用一層新油漆蓋掉？」

爸爸搖搖頭，拿出一本**造車日誌**：「工廠每上一層漆，都會拍一張照片存在日誌裡。你蓋掉了，**前一張照片裡密碼還在**。而且這本日誌是跟著車子一起交出去的。」

> 這就是**不要把秘密 bake 進 image**：用 `ENV` 寫死、用 `ARG` 傳進去、`COPY` 進來再 `RUN rm`，全部都會留在 image 裡。`docker history`（造車日誌）、`docker image inspect`（看車身）一下就看到。image 推上 registry，就等於開到街上給所有人看。

---

## 便利貼還是會被看到

小桃說：「那把密碼寫在**便利貼**上，每天早上貼在駕駛座，不就不會漆在車上了嗎？」

爸爸說：「好多了！至少車子賣掉、借給別人時，密碼不會跟著走。可是你想想——**誰能打開駕駛座的門，誰就能看到便利貼**。坐在旁邊的助手、修車的師傅、拍駕駛座照片傳給朋友的人……」

> 這就是**環境變數的限制**：比 bake 進 image 好太多，但 `docker inspect` 看得到、子行程會繼承、程式不小心把所有設定印進 log 時也會外洩。

---

## 封好的信封，放進專用信箱

爸爸最後想出的方法是：駕駛座旁邊裝一個**小小的專用信箱**，信箱上寫著「祕密專用」。

每天早上，媽媽把密碼寫在紙上，**封進信封**，投進這個信箱。

工作單上不寫密碼，只寫一句話：「**保險箱密碼請看祕密信箱的第一封信**。」

這樣一來，就算有人偷看工作單，也只看到「去看信箱」這幾個字。要開保險箱時，爸爸才打開信箱、拆開信封、看一眼，然後放回去。

> 這就是**檔案掛載的秘密**：把秘密掛成 container 裡的檔案（慣例放在 **`/run/secrets/`**），環境變數只放**路徑**。很多官方 image 支援 **`_FILE` 慣例**：`POSTGRES_PASSWORD_FILE=/run/secrets/db_password`，`docker inspect` 只看得到路徑，看不到密碼。

## 資料夾自己也要藏好

媽媽寫給爸爸的那本工作資料夾，裡面也有收貨人的電話和一些密碼。

小桃發現媽媽在家裡放了兩本：一本叫「**範本**」，上面寫著「密碼：（請自己填）」，放在大家都能翻的書架上；另一本是**真正填好的**，鎖在抽屜裡，從來不拿出去給別人影印。

> 這就是 **`shorty.env.example` 進 git、`shorty.env` 不進 git**。`.gitignore` 和 `.dockerignore` 就是那個抽屜的鎖：一個讓它不被 commit，一個讓它不被 `COPY` 進 image。

## 回到現實：故事 ↔ Docker 對照表

| 故事裡的東西 | 真正的 Docker 概念 |
|------|------|
| 照設計圖做出來的點心車 | **image**（一個 image 跑所有環境） |
| 三個城市（海邊、學校、夜市） | dev／staging／production |
| 每天出門前貼的工作單 | **環境變數**（12-factor config） |
| 便利貼 | **`-e KEY=VALUE`** |
| 一整本工作資料夾 | **`--env-file`** |
| 「引號十點引號」 | `--env-file` 不會去掉引號 |
| 漆在車身上的密碼 | `ENV` 寫死秘密（`docker image inspect` 看得到） |
| 漆在底盤再蓋掉 | `ARG`／`COPY` 再 `RUN rm`（前一層還在） |
| 造車日誌與每一層的照片 | **`docker history`** 與 image layer |
| 車子開到街上 | `docker push` 到 registry |
| 便利貼會被坐旁邊的人看到 | 環境變數在 `docker inspect` 看得到 |
| 祕密專用信箱 | **`/run/secrets/`** |
| 「請看信箱的第一封信」 | **`_FILE` 慣例**（`POSTGRES_PASSWORD_FILE`） |
| 書架上的範本 | **`shorty.env.example`** |
| 鎖在抽屜裡的真本 | **`shorty.env`**（`.gitignore`、`.dockerignore`） |

## 一句話記住

> **車子只做一台、工作單每天貼（環境變數）；密碼不能漆在車上（bake 進 image），最好封進信封放專用信箱（/run/secrets）。**
